# دليل مشروع DMS (Claude Project Guide)

نظام إدارة وثائق إلكتروني لشركة **«أرض العرين للتجارة والمقاولات» (DEN LAND)** — متعدد الشركات، عميل سطح مكتب يتصل بـ API مركزي **مستضاف على سيرفر داخل مكتب الشركة** (ADR-016).

## 1) المرجع الأساسي
- **خطة العمل الكاملة:** [`خطة-العمل.md`](../خطة-العمل.md) (الإصدار 2.2 — معتمدة ومُراجَعة تقنياً). هي مصدر الحقيقة للنطاق والقرارات.
- **توثيق التنفيذ:** مجلد [`.claude/docs/`](docs/).

## 2) التقنيات المعتمدة (Tech Stack)
| الطبقة | التقنية |
|---|---|
| الباك-إند | ASP.NET Core Web API (.NET 9) + EF Core 9 |
| قاعدة البيانات | SQL Server — تطويراً المثيل الافتراضي (`Server=.`)، إنتاجاً **SQL Server Express** على السيرفر الداخلي |
| توليد PDF | **QuestPDF** (أصلي، RTL، بلا متصفح) |
| تصدير Word | **OpenXML** (DocumentFormat.OpenXml) |
| توقيع QR | **ECDSA P-256** (مفاتيح إنتاج تُولَّد على السيرفر وتُحمى بـ **BitLocker + NTFS**) |
| المصادقة | JWT + Refresh + BCrypt |
| التخزين | تجريد `IFileStorage` — **قرص السيرفر** (`LocalFileStorage`) تطويراً وإنتاجاً |
| الاستضافة | **سيرفر داخلي (Mini PC) + Cloudflare Tunnel** — خدمة ويندوز (ADR-016) |
| الواجهة | Flutter (ويب حالياً؛ بناء Windows `.exe` مؤجَّل — يتطلب VS C++ workload) |
| الخط العربي | Amiri (OFL) مضمّن + Cairo/Arial/Times New Roman |

> ⚠️ **عُدل نهائياً عن Azure و DigitalOcean** (ADR-016، 2026-07-22): لا Azure SQL، ولا Azure Blob، ولا Key Vault.
> القرارات التقنية الكاملة مع مبرراتها: [`docs/decisions.md`](docs/decisions.md).

## 4) أوامر سريعة
```bash
cd D:\DMS\backend
dotnet build Dms.sln                                   # بناء الكل
dotnet run --project Dms.Api                           # تشغيل الـ API (+ Swagger في Development)
dotnet ef migrations add <Name> -p Dms.Infrastructure -s Dms.Api
dotnet ef database update      -p Dms.Infrastructure -s Dms.Api
dotnet run --project Dms.Spike                         # اختبار توليد PDF/QR/Word
```
- أول دخول: `admin` / `Admin@12345` (إجباري تغييرها).
- الأسرار (JWT + مفاتيح QR) في `backend/Dms.Api/appsettings.Development.json` (غير مُدرج في git).

🔴 **ودفعة (2026-08-06 — ADR-028، **مدموجة**، بلا مهاجرة): عطلٌ ماليّ كان قائماً وعولج.** علَم «مدفوع من شركة أخرى» كان **يلوّن السطر ولا يمسّ رقماً**، فاحتُسب في قاعدة العمل **3,680,000 د.ع** ضمن المدفوع في شهرين مُسدَّدين. عولج بـ**قاعدةٍ واحدة** في `Dms.Domain/PayrollPayable.cs` تحكم المواضع الثمانية، و**بوّابة حسمٍ** تمنع التسديد قبل البتّ في كل موظفٍ مزدوج (+ حارس تقادم). ومعها: **قالب شروط العمل** عند الإسناد، و**فكّ الإسناد** مع سجلٍّ يبقى مقروءاً.
البناء **0/0**، و**365 اختبار وحدة**، و**292 اختبار واجهة** (كلها مقيسة بالتشغيل في 2026-09-07)، و**584 تحقّق E2E** — وهو **مجموع آخر تشغيلٍ مُسجَّل** لكلٍّ من السكربتات **التسعة** لا تشغيلٌ واحد للكل (**المهام 146/146 مرّتين متتاليتين** في 2026-09-07). و**٢٨ مهاجرة كلُّها مُطبَّقة على `DmsDb`**. **معايير قبول v1: 10/10.**
🔄 **وأحدث الدفعات (2026-08-10):** الصادر يُرى **بالقسم لا بالمُنشئ** (ADR-030) · إغلاق ثغرة الافتراض في شاشة المستخدمين (D7) · **إغلاق G2** بالعزل والتزامن المُثبَتَين حيّاً · تباعد الأرشيف في التقرير · **G14** تذكُّر قرار الموظف المزدوج · ولوحة التحكم صارت تعرض **«آخر الوارد»** و**الوارد في الرسم الأسبوعي**.
📊 **ودفعة (2026-08-11 — ADR-031، **مدموجة**، بلا مهاجرة): وحدة التقارير اكتملت.** **تقرير النشاط** من سجلّ التدقيق (ترجمة عربية لـ41 فعلاً و22 نوعاً · تجميع بالفعل وبالمستخدم · مفردات فلترة من الخادم) و**التقريران التفصيليان** للصادر والأرشيف، ولكلٍّ **PDF و Excel**.
🔐 **وحدٌّ مزدوج على الثلاثة:** النشاط يشترط قسم التقارير **مع دور رئيس الشركة فأعلى** (سجلّ التدقيق يكشف بيانات كل الأقسام، ونظيرُه `/api/audit` مقصورٌ عليهما)، والتفصيليان يشترطان قسم التقارير **مع قسم وحدتهما** — وإلا صار التقرير باباً خلفياً.
🔴 **وكشف التشغيل عيباً حقيقياً:** **188 سطر دخول في قاعدة العمل بلا فاعل** — لأن `UserId` يُكتب فارغاً لحظة الدخول (لا مستخدمَ مصادَقاً بعد) والفاعل في `EntityId`. عولج في **العرض والفلترة والتجميع** معاً.
🔧 **ودفعة (2026-08-12 — ADR-032، بلاغات المالك بعد اختباره التقارير):** **تقريرٌ واحد للمال** (التبويب المالي مخفيّ لأن الصادر التفصيلي يغنيه) · **بلا عمود مبالغ في الأرشيف** · و🔐 **النشاط للسوبر أدمن وحده** — و`/api/audit` معه، لأن التقرير **رقابةٌ على المستخدمين بمن فيهم الرئيس**.
🔴 **ومعها عائلتا أعطال:** (١) **كل وقتٍ في النظام كان متأخّراً ٣ ساعات** لأن الخادم يرسل التاريخ بلا `Z` فيقرؤه Dart محليّاً — عولج بـ`parseInstant` على ثمانية حقول، **والتواريخ التقويمية لم تُمسّ عمداً**. (٢) **شاشة الوارد تسقط** بمنسدلةٍ قيمتُها تسبق قائمتها — عولج بـ`safeDropdownValue` في **ثلاثة مواضع** (أُصلح نظيرُها في موضعٍ واحد سابقاً فبقي اثنان ينتظران بلاغاً).
👤 **ودفعة (2026-08-19 — ADR-033، **مدموجة ومهاجرتُها مُطبَّقة**): البروفايل الشخصي.**
كل حساب يرى **بياناته هو**: هويّةٌ للقراءة (**لا تعديل للاسم إطلاقاً** — قرار المالك) · **إجازاتي**
بطلبٍ ذاتيّ معلّقٍ دائماً · **راتبي أنا** للأشهر المُسدَّدة وحدها + إيصال PDF.
🔐 **و`[Authorize]` وحده بلا قسم ولا دور — وهذا مقصود:** قسم الرواتب يفتح رواتب **الشركة**
وهذا يفتح **راتبك أنت**، فاشتراطُ الأول للثاني يعني ألّا يرى الموظف راتبه إلا إذا رأى رواتب
زملائه. **والحارس الوحيد** أن كل نقطة تشتقّ الموظف من `Employee.UserId == current.UserId`
ولا تقبل معرّفاً من العميل — **مُثبَتٌ بالتشغيل**: `/employees` و`/payroll` تردّان عليه 403 في
اللحظة نفسها.
🔴 **وقرار الحسم يتّخذه المراجع لا الطالب:** الطلب الذاتيّ يصل بـ`DeductFromSalary = false`
**كغيابِ قرار لا كقرار**، والفرق لا يظهر في نوع البيانات — فلو مرّ الافتراض صامتاً لاحتُسبت
إجازةُ شهرٍ بلا راتب مدفوعةً. القاعدة في `Dms.Domain/LeaveDecision.cs` وحدها.
🔴 **وعائلة عطل الوقت (ADR-032) كانت أوسع:** `models_hr.dart` **لم يُمسّ أصلاً**، فبقيت **ستة
حقول** متأخّرة ٣ ساعات — عولجت، والتواريخ التقويمية لم تُمسّ.
✅ **وعيبٌ سابقٌ كشفه التشغيل على قاعدة نظيفة ثم عولج (G16 ⟵ ADR-034):** سجلّ تعديلات
الشهر المُسدَّد كان يعود **فارغاً** إذا كان المعدِّل سوبر أدمن غير مُسنَد لشركة — والـinner
join على `db.Users` المفلتر كان يمحو **القيد كلَّه** لا اسم فاعله. الآن السطور تُقرأ أولاً
ثم الأسماء باستعلامٍ ثانٍ، و**السطر يبقى ولو تعذّر اسم فاعله**. ومعه **G17** (فشلان كاذبان
في `hr-e2e.ps1`): **97/5 ⇐ 151/151 على قاعدةٍ نظيفة**.
✅ **وتمّت بها عائلة عطل الوقت كلُّها (G18):** الحقول الثلاثة الباقية في `models_hr.dart`
— `changedAt` و`uploadedAt` و`otherPaidAt` — صارت `parseInstant`، ومعها `.toLocal()` في
موضع العرض الوحيد الذي كان بلا تحويل. **والتواريخ التقويمية لم تُمسّ**، وحارسٌ صريح يثبّت
ذلك ضمن **٤ حرّاس مُثبَتٌ أنهم يحرسون**.
🖼️ **ودفعة (2026-08-19 — ADR-035، بعد اختبار المالك البروفايل حيّاً): الصورة يغيّرها صاحبها،
والاسم لا.** `POST /profile/photo` **بلا معرّف** (البطاقة تُشتقّ من الجلسة)، وزرّ كاميرا
**يغيب لمن لم يُربط**. 🔴 **ومبدأ «صورةٌ واحدة للشخص» بقي بالبناء لا بالنيّة:** الكتابة على
`Employee.PhotoBlobKey` نفسه — **مُثبَتٌ بالتشغيل** أن بطاقة شؤون الموظفين تقرأ ما رفعه
الموظف. والقاعدة انتقلت إلى `Dms.Domain/EmployeePhoto.cs` لأن للصورة **مسارَين** الآن.
🔐 **والاسم يبقى كما هو بقرار المالك، وثلاثة حقولٍ لا واحد:** اسم المستخدم **ثابت**؛
و`User.FullName` تحت قسم **المستخدمون** لأنه **اسمُ الفاعل في سجلّ التدقيق** — من يعدّله
يعيد تسمية فاعلٍ في سجلّ الرقابة؛ و`Employee.FullName/En` تحت **`CanManageEmployees`** لأنه
اسم الإيصالات والكشوف. **تسميةٌ للعرض وتسميةٌ للمساءلة، ولا يُخلطان.**
🔴 **ودفعة (2026-08-20 — ADR-036، الدفعة أ من ملاحظات المالك العشر): عطلٌ ماليّ عولج.**
`PayrollService` **لم يكن يقرأ جدول الإجازات إطلاقاً** — التوليد يكتب `AbsenceDays = 0`،
فإجازةٌ مقبولةٌ بعلَم «تُحسم من الراتب» **لا تُنقص ديناراً ولا تُصدر تنبيهاً**. عائلة
ADR-028 نفسها: **علَمٌ يلوّن سطراً ولا يمسّ رقماً**.
✅ **والعلاج تنبيهٌ رابع في الكشف بزرَّين — لا حسمٌ تلقائيّ** (قرار المالك، ونهجُ الوحدة
المُثبَت: «اقتراحٌ لا حكم»): **«طبّق»** يُضيف الأيام قابلةً للتعديل، و**«صرف النظر»** يبتّ
بلا مساسٍ برقم. 🔴 **وزرّان لا زرّ لأن `ReviewAsync` يرفض تغيير قرار الإجازة بعد البتّ
(409)** — فالتراجع يقع في الكشف لا في السجلّ.
📅 **وقاعدتان في `Dms.Domain/LeaveDeduction.cs`:** الإجازة العابرة للشهرين **تُقسَم
بالأيام** (٢٨ آب ← ٣ أيلول = ٤ + ٣)، والواقعة في شهرٍ **مُسدَّد تُرحَّل** إلى الكشف المفتوح
بعلَم تأخّر ومنسوبةً لشهرها — ⚠️ **وما دام شهرها مسودّةً لا تُرحَّل** وإلا حُسمت من الشهر
الخطأ. و`EmployeeLeaveSettlement` مفتاحه **(الإجازة × شهر الأيام)** لأنها تُبتّ مرّتين.
🗑️ **ومعها زرّ إفراغ المسودّة** — النقطة وعميلها موجودان منذ ADR-023 بلا زرّ (**سادس**
تكرارٍ لنمط «ميزة بلا مدخل»).
⏳ **وبقيت أربع دفعات من ملاحظات المالك:** البحث الحيّ وكلمة المرور والشريط العلوي (ب) ·
صور الموظفين والتكبير (ج) · تبويبات ملفّ الموظف وفلتر السنوات (د) · التفويضات والقالب
الافتراضي (هـ).
🎯 **ودفعات (2026-09-06/07 — ADR-037 · 038 · 039، **كلّها مدموجة ومهاجراتُها الثلاث مُطبَّقة**):
الوحدة الحادية عشرة — المهام.** ستّ دفعاتٍ من سبع.
🔐 **قسمٌ ثالثٌ حسّاس يُمنح صراحةً** (`Tasks = 512` + `CanManageTasks`)، و**الحارس عُمِّم**:
`RequireHrModule` ⇐ **`RequireGrantedModule`** — لأنه لم يكن خاصّاً بالموظفين قطّ، **ونسخُ
قاعدة الصلاحية أوّلُ الطريق إلى تباعدها**.
🔴 **وقاعدة الرؤية في `TaskService.Query()` وحدها**: الأدوار العليا وصاحبُ العلَم يرون كل
مهام الشركة، وغيرُهم ما هو **مسؤولٌ عنه أو أنشأه أو أُسند لقسمه أو هو مشاركٌ فيه** —
**والمرفقات تناديها ولا تنسخها**.
📅 **«الموعد يومٌ لا لحظة»** (`LocalClock`): التواريخ التقويمية `Unspecified` — و`DateTime.UtcNow`
يورّث `Kind` صامتاً فتخرج بصيغتين على السلك (**عائلة ADR-032 مقلوبةً**).
🔴 **وسبعة أعطالٍ كشفها التشغيل لا المراجعة، ثلاثةٌ منها تكرارٌ لـADR-034** (`Include` على
علاقةٍ مطلوبة نحو جدولٍ مفلتر ⇒ `INNER JOIN` **يحذف الصفّ**) — أشهرُها بلاغ المالك «السوبر
أدمن لا يستطيع إنشاء مهمة»: المهمة **تُنشأ** ثم تردّ 404 وتختفي من كل قائمة. 🔑 **والحارس
القائم كان أعمى لأنه يفحص الاسم والصفُّ يُحذف — احرس العدد لا المحتوى.**
👥 **ومسؤولٌ واحد + مشاركون** (قرار المالك): المسؤولية إذا توزّعت ضاعت، والرؤية إذا انقطعت
ضاع السياق. **وسببٌ مكتوب** عند تراجع النسبة وعند تغيير ما يمسّ غيرك — **لا عند كل تعديل**،
فطلبُ السبب فيما لا يستحقّه يُعلّم المستخدم كتابة «تعديل» فيموت الحقل.
🔔 **والإشعارات كيانٌ عامّ (ADR-038)** — `[Authorize]` وحده لأن **الإشعار ملكُ صاحبه**،
وقراءتُه تتجاوز فلتر الشركة **بشرطٍ أضيق** (`RecipientUserId == me`)، و`DedupKey` بفهرسٍ
فريد يمنع الإغراق **في القاعدة لا في النيّة**.
⚙️ **وخدمةٌ خلفية كل ساعة (ADR-039)** — أوّل خدمةٍ **تكتب** بيانات، وأربعة أخطارٍ عولجت
بحرّاس مُثبَتين: 🔴 **الخدمة بلا فلتر شركة إطلاقاً** (لا `HttpContext` ⇒ العزل مُعطَّل) ⇒
تجميعٌ صريح بـ`CompanyId` · الحالة **في أعمدة لا ذاكرة** · فحصُ وجودٍ وفهرسٌ فريد ضدّ التكاثر ·
وحارس الصيانة. **و`POST /tasks/run-jobs` بحارسَي السوبر أدمن والتطوير** لأن «انتظر ساعةً ثم
تحقّق» ليست خطة تحقّق.
**التحقّق:** بناء 0/0 · وحدة **365** · واجهة **292** · **`tasks-e2e` 146/146 مرّتين متتاليتين**.
⏳ **وتبقّت الدفعة ٧:** **لوحة كانبان + تقارير المهام** (PDF/Excel بحدٍّ مزدوج) ← ثم النشر.
أحدث القرارات: الإحالة **متعددة الأقسام وتراكمية** (ADR-018) و**مَن أحال يبقى يرى** ·
**الأرشيف عدسة لا صندوق** مع استيراد بالجملة وفكّ أرشفة (ADR-021) ·
**النسخ على مستويين** مجدولة قاعدة-فقط + مرآة يدوية لا تُكرّر (ADR-020) ·
