# دليل تشغيل المشروع على أجهزة Mac (Apple Silicon)

هذا الدليل يوثق التحديات والحلول التي واجهتنا أثناء تشغيل مشروع DMS (الباك-إند والفرونت-إند) على بيئة macOS وتحديداً الأجهزة بمعمارية أبل (M1/M2/M3) لأول مرة، وذلك لتلافي تكرار هذه الأخطاء مستقبلاً أو عند نقل المشروع لجهاز جديد.

## 1. مشكلة توافقية إصدار .NET SDK
* **المشكلة:** المشروع كان محددًا بصرامة ليعمل على `.NET 9` (النسخة المثبتة في الويندوز)، ولكن جهاز الماك يحتوي على `.NET 10`. هذا أدى إلى ظهور خطأ `A compatible .NET SDK was not found`.
* **الحل:** تم تعديل ملف `global.json` في المشروع والسماح بالترقية التلقائية للإصدارات الأحدث عن طريق تغيير `"rollForward": "latestFeature"` إلى `"rollForward": "latestMajor"`.
* **ملاحظة تشغيلية:** عند تشغيل المشروع على الماك (الذي يحتوي على SDK 10) قد يطالب بتنزيل الـ Runtime الخاص بالإصدار 9. لتجاوز ذلك بدون تنزيلات إضافية، نستخدم أمر التشغيل التالي:
  `DOTNET_ROLL_FORWARD=LatestMajor dotnet run --project backend/Dms.Api`

## 2. مشكلة قاعدة البيانات (غياب LocalDB)
* **المشكلة:** الباك-إند يعتمد على `SQL Server LocalDB` في بيئة التطوير (`appsettings.json`)، وهذا المحرك حصري لنظام Windows ولا يتوفر على أجهزة Mac.
* **الحل:** استخدمنا `Docker` لتشغيل نسخة `Azure SQL Edge` (وهي نسخة خفيفة ومصممة خصيصاً لتعمل بكفاءة على معالجات ARM / Apple Silicon).
* **الأمر المستخدم لإنشاء القاعدة:**
  ```bash
  docker run -e "ACCEPT_EULA=Y" -e "MSSQL_SA_PASSWORD=Sinan@2026Strong" -p 1433:1433 -d mcr.microsoft.com/azure-sql-edge:latest
  ```
* **تحديث الاتصال:** تم تعديل `ConnectionString` في `appsettings.json` ليتصل بـ `localhost:1433` بدلاً من LocalDB.

## 3. خطأ تثبيت Docker Desktop (HTTP 500)
* **المشكلة:** عند تثبيت Docker Desktop وإعداده لأول مرة، تظهر رسالة `HTTP 500: Internal Server Error` ويتم رفض كلمة المرور. هذا خلل برمجي (Bug) معروف في واجهة إعداد Docker على الماك.
* **الحل لتجاوز الخلل:**
  1. إعادة تشغيل البرنامج واختيار `Use advanced settings`.
  2. تحديد خيار إعداد الـ CLI Tools كـ `User` بدلاً من `System`.
  3. إزالة علامة الصح عن الصلاحيات التي تتطلب كلمة مرور (Default Docker socket & Privileged port mapping).
  4. الضغط على Finish، ليعمل البرنامج بدون المطالبة بصلاحيات النظام الحساسة.

## 4. فقدان مفاتيح التشفير (User Secrets)
* **المشكلة:** في الويندوز، استخدم المطور أداة `dotnet user-secrets` لحفظ مفتاح `Jwt:SigningKey` ومفاتيح `QrSigning` خارج الكود لحمايتها. عند تحميل الكود على الماك الجديد، هذه المفاتيح مفقودة (`""`) مما يتسبب بانهيار الخادم بـ `Internal Server Error 500` عند محاولة تسجيل الدخول (لأنه لا يجد مفتاحاً لتشفير الـ Token).
* **الحل:** تم إدراج مفاتيح صالحة (طويلة وآمنة) وتثبيتها مؤقتاً في ملف `appsettings.json` لضمان عمل المشروع مباشرة بعد التنزيل على أي بيئة محلية. (في بيئة الإنتاج يجب استبدالها عبر متغيرات البيئة).

## 5. خطأ الفراغ المنطقي (Loop) في واجهة اختيار الشركة
* **المشكلة:** واجهة المستخدم تجبر الـ SuperAdmin على اختيار شركة قبل الدخول، وتقول "لا توجد شركات. أنشئ شركة من الإعدادات". ولكن لا يوجد زر للانتقال للإعدادات! بما أن قاعدة بيانات الماك جديدة وفارغة 100%، علق النظام هنا.
* **الحل:** تم تعديل ملف `DbSeeder.cs` في الباك-إند ليقوم بتكوين شركة افتراضية (`أرض العرين للتجارة والمقاولات`) بشكل تلقائي في حال اكتشف أن قاعدة البيانات فارغة تماماً من الشركات، تماماً كما يفعل مع حساب الـ Admin.
