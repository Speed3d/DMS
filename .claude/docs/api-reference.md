# مرجع الـ API

كل المسارات تحت `/api`. الاستجابات JSON (enums كنصوص). المصادقة: `Authorization: Bearer <JWT>`.
الشركة الفعّالة تُحدَّد بترويسة `X-Company-Id: <id>`: السوبر أدمن (اختياري؛ بلا ترويسة = يرى الكل)، والمستخدم متعدد الشركات (ضمن شركاته المسموحة `companyIds`؛ بلا ترويسة = أول شركة).

**صلاحيات الأقسام (ADR-012):** كل مستخدم له مجموعة أقسام مسموحة `modules` (من الأقسام السبعة: `Outgoing`, `Incoming`, `Archive`, `Reports`, `Users`, `Settings`, `Backup`). الوصول لمسارات القسم المحجوب يُرجِع **403**. السوبر أدمن ورئيس الشركة معفيان (كل الأقسام). «الإعدادات» يحكم كتابات الشركات/القوالب فقط.

## المصادقة — `/api/auth`
| الطريقة | المسار | الوصول | الوصف |
|---|---|---|---|
| POST | `/login` | عام | `{username,password}` → توكنات + `companyIds` + **`companies[]`** (الوصول لكل شركة) |
| POST | `/refresh` | عام | `{refreshToken}` → توكنات جديدة (تدوير) + `companies[]` محدّثة |
| POST | `/logout` | مصادَق | إبطال refresh token |
| GET | `/me` | مصادَق | بيانات المستخدم — `modules`/`canApprove`/`departmentId`/`canManageIncoming` تخصّ **الشركة الفعّالة** |

> **⚠️ `companies[]` مقابل `/me` (ADR-017):** استجابة الدخول تُرجِع الوصول **لكل شركة** لتتبدّل القائمة الجانبية مع تبديل الشركة بلا إعادة دخول. أما `/me` فيُرجِع القيم **المحسوبة للشركة الفعّالة** للطلب.
> **السوبر أدمن قد يكون بلا إسناد شركات** فتعود `companies[]` فارغة — وهو معفى ويرى كل شيء. لمعرفة صلاحيته الفعلية استخدم `/me` لا استجابة الدخول.
| POST | `/change-password` | مصادَق | `{currentPassword,newPassword}` |

## الشركات — `/api/companies`
| GET `/` · GET `/{id}` | مصادَق | قائمة/عنصر (يقتصر على شركات المستخدم المسموحة `companyIds`؛ السوبر أدمن يرى الكل) |
| POST `/` | **SuperAdmin** | إنشاء شركة |
| PUT `/{id}` | SuperAdmin/President | تعديل (التعطيل عبر `isActive=false`) |
| POST `/{id}/logo` | SuperAdmin/President/Manager | رفع الشعار (PNG/JPG ≤ 2MB) |
| GET `/{id}/logo` | عام | جلب الشعار |
| DELETE `/{id}` | **SuperAdmin** | حذف جذري **محروس**: يُمنع (409) مع وجود كتب معتمدة أو أرشيف — عطّل الشركة بدل حذفها |

## القوالب — `/api/templates`

| POST `/` · PUT `/{id}` | SuperAdmin/President/Manager |
| POST `/{id}/images/{kind}` | Manager+ | رفع صورة (`header`/`footer`/`watermark`) multipart `file` |
| GET `/{id}/images/{kind}` | مصادَق | جلب الصورة |

## القوائم
- `/api/entities` — GET (مصادَق) · POST/PUT/DELETE (Manager+؛ الحذف يُرفض 409 إن كانت مستخدَمة).
- `/api/document-types` — GET (مصادَق) · POST/PUT/**DELETE** (Manager+). الاسم **فريد داخل الشركة** (409 عند التكرار، ويحرسه فهرس فريد في القاعدة). **الحذف يُرفض بـ409** إن كان النوع مستخدَماً في وارد أو أرشيف **غير محذوف** ويذكر العدد لكلٍّ منهما. تُبذَر 8 أنواع افتراضية لكل شركة جديدة.
- `/api/departments` — GET (مصادَق) · POST/PUT/DELETE (Manager+). الأقسام: وجهة إحالة الوارد ومكان عمل الموظف (ADR-015). الحذف يُرفض 409 إن كان محالاً إليه كتب واردة (يُقترح التعطيل).
  - `GET /?companyId=` — أقسام **شركة بعينها**، للسوبر أدمن ورئيس الشركة فقط (403 لغيرهما، و403 للرئيس خارج شركاته). يلزم لملء نموذج المستخدم متعدد الشركات (ADR-017)؛ بدونه تُرجَع أقسام الشركة الفعّالة وحدها.
- `/api/exchange-rates` — GET `/` · GET `/latest?currency=USD` · POST (Manager+).

## المستخدمون والتفويض
- `/api/users` (SuperAdmin/President/Manager + قسم `Users`): GET، POST، PUT `/{id}`، POST `/{id}/reset-password`. الهرمية والعزل مفروضان في الخدمة.
  - المدخلات تحمل `companyIds` و`modules` (قائمة أسماء الأقسام). **ربط الشركات وتحديد الأقسام حصراً للسوبر أدمن ورئيس الشركة**؛ المدير/الموظف لا يغيّرانها (تُتجاهل ← افتراضي). أدوار السوبر أدمن/الرئيس تُخزَّن بكل الأقسام. غير السوبر أدمن يلزمه شركة واحدة على الأقل. الاستجابة تُعيد `companyIds` و`modules`.
  - **⚠️ الصلاحيات صارت لكل شركة (ADR-017):** المدخلات تحمل `companies: [{companyId, modules, departmentId, canApprove, canManageIncoming, canViewAllIncoming}]` بدل الحقول المفردة، والاستجابة تُرجِع نفس الشكل. `null` = «لا تغيير» (يمنع مسح الإسنادات عند تعديل حقل آخر). **المدير فأعلى يملك `canApprove` و`canManageIncoming` بحكم دوره** في كل شركاته. كل `departmentId` يُتحقَّق منه مقابل **شركة صفّه** (خطأ 400 إن كان من شركة أخرى).
- `/api/delegations` (Manager+): GET، POST، DELETE `/{id}`.

## الوارد — `/api/incoming`
يتطلب قسم `Incoming`. **قاعدة الرؤية (ADR-015):** المدير فأعلى يرى كل كتب الشركة؛ والموظف/القارئ يرى **الكتب التي استلمها + كل الكتب المُحالة إلى قسمه** (`User.DepartmentId`). موظف بلا قسم يرى كتبه فقط.

| الطريقة | المسار | الوصف |
|---|---|---|
| GET | `/?search=&status=&entityId=&from=&to=&documentTypeId=&departmentId=&receiveMethod=` | بحث (نصّي في الرقم الداخلي/الخارجي والموضوع والكلمات المفتاحية والملاحظات واسم الجهة). قيمة `status` أو `receiveMethod` غير صحيحة → **400**. `departmentId` يُطابق **أي إسناد** لهذا القسم (ADR-018). الموظف/القارئ يرى: كتبه + كتب قسمه (ADR-015) + **ما أحاله بنفسه** (ADR-018). العنصر يحمل `departmentNames: []` |
| GET | `/{id}` | تفاصيل (اسم الجهة ونوع المستند واسم المستلم ورقم الصادر المرتبط) + `departments: [{departmentId,name,note,assignedByUserName,assignedAt}]` — الأقسام المُحال إليها (ADR-018) |
| POST | `/` | تسجيل كتاب وارد (Employee+) — **ترقيم فوري** `PREFIX-IN-YEAR-#####`، الحالة الابتدائية `New` |
| PUT | `/{id}` | تعديل — المدير فأعلى في أي حالة عدا `Archived`؛ المنشئ في حالة `New` فقط |
| POST | `/{id}/status` | ⚠️ يُرجِع **204 بلا جسم** إن نجحت العملية و**لم يعُد المنفِّذ يرى الكتاب** (أرشفة مثلاً). تغيير الحالة `{status,note}` — يخضع لمصفوفة الانتقالات (ADR-013). **الأرشفة للمدير فأعلى دائماً.** الموظف/القارئ: `New→InReview` فقط، **إلا بصلاحية `CanManageIncoming`** فيدير كل الانتقالات عدا الأرشفة (ADR-015). الملاحظة **إلزامية** عند `Replied` يدوياً بلا ربط بصادر |
| POST | `/{id}/forward` | **إحالة إلى قسم واحد أو أكثر معاً (ADR-018):** `{departments:[{departmentId,note}], generalNote}`. **تراكمية** — تُضيف ولا تُزيح؛ وإعادة الإحالة لقسم موجود **تُحدّث ملاحظته** ولا تُكرّره. **قسم واحد غير صالح يُبطل الإحالة كلها (400)** — لا إحالة نصفية. قائمة فارغة → **400**. للحالتين `New`/`InReview` فقط، وتنقل `New` تلقائياً إلى `InReview`. تُنشئ **سطر سجلّ لكل قسم** يدمج ملاحظته مع الملاحظة العامة. **القارئ ممنوع (403)**. ⚠️ قد تُرجِع **204 بلا جسم** إن خرج الكتاب من رؤية المُحيل — نادر الآن لأن **مَن أحال يبقى يرى** |
| POST | `/{id}/link/{outgoingId}` | ربط بصادر **معتمد** (Manager+) → الحالة `Replied`. يُرفض على المغلق/المؤرشف، ويُرفض الربط المزدوج من الطرفين (**409**) |
| DELETE | `/{id}/link` | فك الارتباط (Manager+) — يُعيد `Replied` إلى `InReview`؛ يُرفض على المؤرشف أو بلا ارتباط (**400**) |
| DELETE | `/{id}` | حذف ناعم — المنشئ وهو `New`؛ المدير فأعلى لبقية الحالات؛ **المؤرشف: SuperAdmin فقط** |
| GET | `/{id}/movements` | سجل الحركة مع أسماء المنفّذين — **لكل من يستطيع الإحالة**، أي كل الأدوار عدا **القارئ** (403). قرار المالك: من يقرّر الوجهة التالية يحتاج أن يعرف أين مرّ الكتاب |
| GET/POST | `/{id}/attachments` | قائمة/رفع مرفق — **الصلاحية = نفس قاعدة رؤية الكتاب** (ADR-015): مَن يرى الكتاب يرى مرفقاته ويرفع عليها |
| DELETE | `/{id}/attachments/{attachmentId}` | حذف مرفق (غير القارئ) |
| GET | `/{id}/attachments/{attachmentId}/download` | تنزيل مرفق (يتطلب مصادقة) |

> **الربط العكسي:** `GET /api/outgoing/{id}` يُرجِع `replyToIncomingId` و`replyToIncomingNumber` للكتاب الوارد الذي يردّ عليه.

## النسخ الاحتياطي — `/api/backup` (SuperAdmin فقط)
| الطريقة | المسار | الوصف |
|---|---|---|
| GET | `/` | قائمة النسخ (يتضمّن `scope` و`category`) |
| POST | `/run` | نسخة يدوية فورية (كاملة: DB + ملفات → ZIP) |
| GET | `/coverage` | **تغطية النسخ:** عمر آخر نسخة **كاملة** وإلحاحها — `Ok` · `Soon` (٣ أيام) · `Urgent` (يوم/يومان) · `Overdue` (≥٣٠ يوماً **أو لم تُؤخذ قط**). المجدولة صارت قاعدة-فقط فهي لا تحمي المرفقات (ADR-020) |
| POST | `/mirror` | **مرآة كاملة** إلى `targetPath` يحدّده المالك (قرص خارجي). **تُضيف ولا تُكرّر** — الموجود بالحجم نفسه يُتخطّى. المسار يُفحص: مطلق بحرف قرص · ليس مجلد نظام · ليس داخل التخزين أو مجلد النسخ (400) |
| POST | `/mirror/restore` | استعادة من مرآة (`sourcePath` + `confirmation="استعادة"`) — تدميرية، تأخذ نسخة أمان أولاً |
| POST | `/{id}/restore` | **استعادة** — `{confirmation:"استعادة"}`. تأخذ نسخة أمان أولاً ثم تدخل وضع الصيانة (ADR-014) |
| GET | `/schedule` | إعداد الجدولة الحالي |
| PUT | `/schedule` | تحديث الجدولة `{frequency:Off/Daily/Weekly, enabled, hour}` — «يومي» يُنتج دورة جد/أب/ابن تلقائياً |
| GET | `/{id}/download` | تنزيل أرشيف النسخة (ZIP) |

> **النطاق والاحتفاظ (ADR-014):** اليومية «قاعدة فقط» (خفيفة)، والأسبوعية/الشهرية/اليدوية كاملة. الاحتفاظ: 7 يومية · 4 أسبوعية · 12 شهرية · 20 يدوية (التقليم تلقائي بعد كل نسخة ناجحة).

## الموظفون — `/api/employees` (ADR-023)

> 🔐 **كل مسارات هذا الملف تحت `[RequireHrModule(AppModule.Employees)]`: القسم **و** دورٌ
> فوق القارئ (ADR-025).** والكتابة تتطلّب فوق ذلك **`CanManageEmployees`**
> (السوبر أدمن ورئيس الشركة معفيان بدورهما).
>
> 🔴 **وقسم «الموظفين» لا يفتح «الرواتب»:** صاحبه يُحجب بـ403 عن كل `/api/payroll`
> وعن `/hr/settings`. والقارئ محجوب عن الاثنين مهما مُنح.

| الطريقة | المسار | الوصف |
|---|---|---|
| GET | `/` | موظفو الشركة الفعّالة — `?activeOnly=true/false&search=` |
| POST | `/` | موظف جديد + إسناده للشركة الفعّالة (`{profile, employment}`) |
| GET | `/{id}` | تفاصيله **مع إسناداته في الشركة الفعّالة وحدها** في `companies`، و**أسماء** الشركات الأخرى في `otherCompanies` (ADR-027) |
| PUT | `/{id}` | تحديث البيانات الشخصية |
| PUT | `/{id}/employment` | إنشاء/تحديث شروط عمله **في الشركة الفعّالة**. ⚠️ لا يقبل `companyId` من العميل — من أراد شركةً أخرى بدّل شركته الفعّالة |
| POST | `/{id}/terminate` | إنهاء الخدمة `{terminationDate, reason, notes}` |
| DELETE | `/{id}` | حذف ناعم — **مرفوض (409)** لمن له رواتب مُسدَّدة |
| GET | `/lookup?nationalId=` | البحث عن موظف قائم قبل إنشاء ملف ثانٍ له. **يتجاوز الفلتر عمداً** ويعيد الاسم فقط + هل هو في شركتك. غير موجود ⇒ **204**. يتطلّب `CanManageEmployees` |
| GET | `/{id}/employment-template` | **شروط عمله في شركةٍ أخرى** لتعبئة نموذج الإسناد (ADR-028): الصفة والعملة والراتب + اسم الشركة المصدر. **بلا تاريخ تعيين عمداً**. 🔐 مرفوض (400) لمن هو مُسنَدٌ هنا · يتطلّب `CanManageEmployees` · **ويُسجَّل في التدقيق**. لا يوجد ⇒ 204 |
| DELETE | `/{id}/employment` | **فكّ إسناده عن الشركة الفعّالة** — لا حذفَ ملفّه (ADR-028). `?notes=` سببٌ اختياري يُحفظ في سجلّ تغييراته. **مرفوض (409)** لمن له رواتب مُسدَّدة هنا |
| GET | `/unlinked` | مَن فُكّ إسنادهم عن الشركة الفعّالة — بنفس شكل القائمة. سجلّاتهم تبقى مقروءة عبر `/{id}/log` |
| POST | `/{id}/photo` | رفع صورة (JPG/PNG، 5 ميغا) |
| GET | `/{id}/photo` | الصورة — **بلا اسم ملف** (مبدأ ADR-019: يُعرض ولا يُختطف) |
| GET | `/{id}/salary-history?take=` | آخر رواتبه |
| GET | `/{id}/attachments` | **مستمسكاته** (هوية · عقد · شهادات) — `OwnerType.Employee` |
| POST | `/{id}/attachments` | رفع مستمسك (multipart) |
| GET | `/{id}/attachments/{attachmentId}/download?inline=` | تنزيل أو **عرض داخلي** (مبدأ ADR-019) |

> 🔄 **تغيّر في عقد بطاقة الموظف (2026-08-06 — ADR-027):** `EmployeeDetailResponse` صار يحمل
> **`otherCompanies: [{companyId, name}]`** — أسماءُ الشركات الأخرى التي يعمل فيها، **بلا راتب
> ولا صفة ولا تاريخ تعيين**. حقلٌ منفصل عن `companies` عمداً: الأول واقعةٌ تُعلَم، والثاني
> شروطُ عملٍ تُقرأ. وقائمةٌ فارغة لمن يعمل في شركةٍ واحدة (**لا حقلٌ غائب**).
> 🔐 والحارس قبله: مَن لا يرى الموظف في شركته الفعّالة يأخذ **404** ولا يعرف شركاته.
>
> **ودورة «إسناد موظف قائم» لا تحتاج نقطةً جديدة:** بحثٌ بـ`/lookup` ثم `PUT /{id}/employment`

> 🔄 **تغيّر في عقد السطر (2026-08-05):** `PayrollEntryResponse` صار يحمل **`eligibleDaysIsManual`**
> بعد `eligibleDays` مباشرةً. `false` تعني أن الخادم يُعيد حساب الأيام في كل حفظ (السلوك
> الافتراضي)، و`true` تعني أن مستخدماً ثبّتها بـ`eligibleDaysOverride` فلا تُمسّ.
> ⚠️ **وحساب الأيام نفسه تغيّر إلى عرف 30/360** — الشهر مدى مرقّم `1..workingDays`، فمن عُيِّن
> اليوم 16 يأخذ 15 يوماً في **كل** شهر. (كان يتبع طول الشهر التقويمي فيُصرف في شباط 28/30.)
