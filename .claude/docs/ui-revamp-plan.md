# خطة التطوير الشاملة لواجهات النظام (UI Revamp Plan)

**تاريخ الخطة:** 1 يوليو 2026
**الهدف:** تحويل شكل ومظهر مشروع DMS الحالي (Flutter) ليتطابق بنسبة 100% مع التصميم المرفق (`DMS - الواجهة الجديدة.dc.html`)، مع تضمين المكتبات الخارجية اللازمة لضمان الاحترافية العالية.

---

## 1. التجهيزات والمكتبات الأساسية (Prerequisites)
قبل البدء بتعديل الواجهات، سيتم إضافة الحزم (Packages) التالية إلى `pubspec.yaml`:
- `fl_chart`: لبناء الرسوم البيانية التفاعلية في لوحة التحكم.
- `flutter_quill`: لبناء محرر النصوص الغني (Rich Text Editor) لكتابة محتوى الكتب.
- `flutter_svg`: (إن لزم) للتعامل مع أي أيقونات من نوع SVG.
- تحديث `google_fonts` لدعم خط Cairo بشكل ممتاز.

---

## 2. المراحل التنفيذية (Phases of Execution)

### المرحلة الأولى: الأساسيات ونظام الألوان والهيكل العام (Foundation & Shell)
**المهام:**
- [ ] إنشاء ملف `lib/core/theme.dart` لتعريف الـ `ThemeData` المخصص (ألوان Navy، Gold، Success، وغيرها) للوضع الفاتح والداكن.
- [ ] إنشاء مكونات واجهة مشتركة (Reusable Widgets) مثل:
  - `CustomCard`: للبطاقات ذات الظلال الدقيقة.
  - `StatusPill`: العلامات الملونة لحالة الكتاب (معتمد، مسودة).
- [ ] بناء القائمة الجانبية المحدثة (`Sidebar`) بألوان التدرج الداكن (Navy Gradient) وإضافة قسم "وضع المزامنة".
- [ ] بناء الشريط العلوي (`Topbar`) ليتضمن البحث، زر التحقق من QR، الإشعارات، وملف المستخدم.
- [ ] إعادة تصميم شاشة تسجيل الدخول (`login_screen.dart`) لتطابق التصميم الفاخر تماماً.

### المرحلة الثانية: لوحة التحكم (Dashboard)
**المهام:**
- [ ] تصميم بطاقات الإحصائيات الأربع (Stats Cards) مع تأثيرات الخلفية المضيئة (Glow).
- [ ] استخدام مكتبة `fl_chart` لبرمجة قسم "حركة الصادر" (Bar Chart) ليظهر إحصائيات آخر 7 أشهر بشكل تفاعلي.
- [ ] تصميم قسم "بانتظار اعتمادك" (Pending Approvals) لعرض الكتب التي تحتاج مراجعة كقائمة تفاعلية.
- [ ] تصميم قسم "آخر النشاطات" (Recent Activities).
- [ ] ربط جميع هذه الأقسام بالـ API الفعلي (عبر Riverpod) لجلب البيانات الحقيقية.

### المرحلة الثالثة: نظام الصادر (Outgoing System)
**المهام:**
- [ ] **قائمة الصادر (`outgoing_list_screen.dart`):** تصميم الجدول بشكل احترافي مع علامات الحالة (Pills)، وأزرار التصفية (الكل، مسودات، معتمدة)، وشريط البحث السريع.
- [ ] **تفاصيل الصادر (`outgoing_detail_screen.dart`):**
  - بناء المعاينة التقريبية للـ PDF (Mock Preview) كما في التصميم، تظهر شعار الشركة، الرقم، التاريخ، والـ QR.
  - بناء اللوحة الجانبية (Side Panel) لعرض التفاصيل المالية وحالة الاعتماد.
  - برمجة أزرار الإجراءات (اعتماد، PDF، تعديل، طباعة).
  - قسم "سجل الإصدارات" (Version History).
- [ ] **نموذج الإضافة/التعديل (`outgoing_form_screen.dart`):**
  - دمج `flutter_quill` لعمل محرر نصوص احترافي يحتوي على أدوات التنسيق (Bold, Italic, Lists).
  - تصميم حقول الإدخال وتنسيقها بشكل جميل.
  - تضمين الحقول المالية (المبلغ والعملة).
  - برمجة زر الإرسال لربط البيانات المدخلة وتنسيقات الـ HTML مع الباك-إند بنجاح.

---

## 3. التحديات المتوقعة وكيفية تذليلها
1. **تحويل تنسيقات `flutter_quill` إلى HTML:** بما أن الـ API يتوقع `BodyHtml`، سنقوم باستخدام المحولات المتاحة لترجمة مخرجات Quill (Delta) إلى كود HTML قبل الإرسال، والعكس عند جلب البيانات.
2. **الرسوم البيانية:** سنحتاج لإنشاء نقطة نهاية (Endpoint) جديدة في الباك-إند (أو تعديل الـ Dashboard API الحالي) لإرجاع الإحصائيات الشهرية للرسم البياني بشكل صحيح ومفصل.

---

## 4. منهجية التوثيق والمتابعة
- بعد انتهاء كل "مرحلة" من المراحل المذكورة أعلاه، سيتم تحديث هذا الملف وملف `progress-log.md` في مجلد التوثيقات لتسجيل ما تم إنجازه، الأخطاء التي ظهرت وتم حلها، وما تبقى من الخطة.
- لن يتم الانتقال للمرحلة التالية إلا بعد التأكد من عمل المرحلة الحالية بنسبة 100% دون أي تأثير سلبي على الوظائف الأساسية للنظام.
