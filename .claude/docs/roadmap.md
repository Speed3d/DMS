## ✅ Phase 2 — الأمان والتحسينات المتقاطعة (Security & Cross-platform)
- [x] **التدقيق الأمني (مكتمل):** حماية الجلسات وتشفيرها عبر `flutter_secure_storage`، إخفاء كلمات المرور (Secrets) من الإعدادات، تفعيل سياسات CORS مشددة، وحماية ضد هجمات Path Traversal.
- [x] **تحديث التوافقية:** ترقية بيئة Dart إلى `3.12.0` وتفعيل سياسة `LatestMajor` للـ .NET لضمان توافقية التشغيل السلس بين أنظمة Windows و Mac.
- [x] **الأرشيف (مكتمل):** باك-إند (ArchiveService + AttachmentService) + Controllers + واجهة كاملة — حقول + مالي + ترقيم تلقائي (`DEN-AR-2026-00001`) + **مرفقات (رفع/تنزيل/حذف، PDF/JPG/PNG/DOCX/XLSX، حد 25MB)** + **بحث نصّي وبفترة زمنية**. اجتاز E2E (إنشاء/بحث/مرفق/تنزيل/حذف).
- [x] **التقرير المالي بالدينار (مكتمل):** يجمع الصادر المعتمد + الأرشيف لفترة، تصفية (تاريخ/جهة/مصدر)، إجمالي بالدينار، **تصدير PDF (QuestPDF) و Excel (OpenXML)** + شاشة بالواجهة. اجتاز E2E.
- [x] **النسخ الاحتياطي (مكتمل):** تحكّم السوبر أدمن — نسخة فورية + جدولة (يومي/أسبوعي بساعة) + خدمة خلفية `BackupScheduler` + سجلّ + تنزيل. النسخة = `BACKUP DATABASE` (.bak) + ملفات التخزين في ZIP واحد. اجتاز E2E (4.5MB، يحوي database.bak + 13 ملفاً). **أُعيد تصميمه 2026-07-22 (ADR-014):** نطاق (`DbOnly`/`Full`) + سياسة احتفاظ جد/أب/ابن (7/4/12/20) + **استعادة من داخل النظام** — اجتاز 13 تحقّق E2E. (رفع OneDrive عبر Graph مؤجَّل — يُغطّى بمزامنة مجلد على السيرفر، المرحلة د.)
- [x] **وضع المسودّات دون اتصال والمزامنة (مكتمل):** استخدام قاعدة بيانات Hive لحفظ المسودات والبيانات المخبأة محلياً (Cache) لدعم بيئة Windows بأمان، مع شاشة خاصة للمزامنة الجماعية عند عودة الاتصال.

- [x] **وحدة الوارد (مكتملة — باك-إند + واجهة):** تسجيل بترقيم فوري `PREFIX-IN-YEAR-#####` · دورة حياة بمصفوفة انتقالات مغلقة (ADR-013) · الإحالة لقسم · الربط ثنائي الاتجاه مع الصادر المعتمد · سجل حركة (Timeline) للسوبر أدمن ورئيس الشركة · مرفقات (50 م.ب، +ZIP/DWG) · بحث متقدم · إدراج في التقرير المالي ولوحة التحكم والإشعارات. اجتاز **72 تحقّقاً E2E** (`backend/e2e/incoming-e2e.ps1`). **مؤجَّل:** قائمة «آخر الوارد» في لوحة التحكم · إدراج الوارد في الرسم البياني الأسبوعي · ربط الصادر بالوارد أثناء إنشاء الصادر · منح مدراء محدّدين رؤية سجل الحركة. (✅ **عارض PDF المدمج أُنجز 2026-07-27**.)

- [x] **نظام الأقسام والإحالة الحقيقية (مكتمل — ADR-015، 2026-07-25):** كيان `Department` معزول بالشركة (إدارة من الإعدادات) · قسم عمل الموظف · وجهة الإحالة بدل النصّ الحر. **القاعدة الجوهرية:** الموظف/القارئ يرى كتبه **+ كل كتب قسمه** — فكتاب مُحال لـ«المالية» صار يظهر لموظفي المالية فعلاً. + صلاحية `CanManageIncoming` (نمط `CanApprove`) تتيح للموظف المخوّل كل انتقالات الحالة عدا الأرشفة. **مؤجَّل:** نظام إشعارات كامل (مقروء/غير مقروء) · توسيع الأقسام للصادر.

- [x] **الإحالة المتعددة (مكتملة — ADR-018، 2026-07-27):** الكتاب يُحال إلى **قسم واحد أو أكثر معاً** عبر كيان `IncomingAssignment` (فريد على كتاب+قسم)، بملاحظةٍ لكل قسم وملاحظة عامة تُدمج في سجلّ الحركة. **تراكمية لا استبدال** · إعادة الإحالة **تُحدّث الملاحظة ولا تُكرّر** · **قسم واحد غير صالح يُبطل الإحالة كلها** (لا إحالة نصفية). ⚠️ **أُلغي `IncomingBook.DepartmentId` المفرد و`FolderName`** — migration بترتيب يدوي **إنشاء ← نقل ← إسقاط**. + **«مَن أحال يبقى يرى»** (بلاغ المالك): الموظف يرى كل كتاب أحاله بنفسه ولو لم يكن مستلِمَه ولا من قسم الوجهة. اجتاز **22 تحقّقاً E2E**، وواجهته **شاشة إحالة منبثقة باختيار متعدد**.

- [x] **عارض المستندات الداخلي (مكتمل — 2026-07-27):** عرض PDF والصور داخل البرنامج للوارد والأرشيف، **بلا إنترنت** (pdf.js مستضاف محلياً في `app/web/pdfjs/`). ⚠️ استغرق أربع فرضيات: السبب الحقيقي كان **مسار وحدة بلا `./`** يرفضه المتصفّح صامتاً فيحبس قفل الحزمة للأبد (ADR-019 + سجلّ التقدّم). وأُصلح معه **حقن HTML الخامّ في تصدير Word** (محوّل HTML→OpenXML).
