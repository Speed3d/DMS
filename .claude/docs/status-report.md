## 6) ما تبقّى — مرتّباً بالأثر

> 📋 البنود الحرجة والعالية صارت **خطة تنفيذ تفصيلية**: [`deployment-plan.md`](deployment-plan.md)

### ✅ أُنجزت المرحلة أ من النشر بالكامل (أ-1 … أ-6)
استعادة النسخة (G1) · سياسة الاحتفاظ والنطاق (G6) · خدمة ويندوز · توليد أسرار الإنتاج (G4 برمجياً) ·
نسخة PDF محلية بعد الاعتماد · سكربت التحديث. **كل الأعمال البرمجية التي لا تحتاج الجهاز اكتملت.**

### 🔴 حرجة (تمنع التسليم — تحتاج قرارك/شراءك)
- **شراء Mini PC + UPS + قرص خارجي** ثم تجهيزه (المرحلة ب).
- **اختيار وشراء الدومين** ثم Cloudflare Tunnel (المرحلة ج).
- **اشتراك OneDrive** وربط النسخ (المرحلة د).
- **اختبار الاستعادة على جهاز نظيف** (المرحلة هـ — غير قابل للتفاوض).

### 🟠 عالية
- تنفيذ إجراءات الأسرار على السيرفر: `generate-secrets` + BitLocker + NTFS (G4 — **الأداة جاهزة، ينقصها الجهاز**).
  ⚠️ **مفاتيح QR الإنتاجية تُولَّد مرة واحدة قبل أول كتاب رسمي** — تغييرها لاحقاً يُبطل التحقق من كل الكتب السابقة.
- مثبّت ويندوز `.exe` (G5).
- اختبارات العزل الصفّي والتزامن (G2).

### 🟡 متوسطة
- تقارير النشاط (من سجل التدقيق) والتقارير التفصيلية للصادر والأرشيف.
- لوحة التحكم: قائمة «آخر الوارد» + إدراج الوارد في الرسم البياني الأسبوعي.
- **ترقية المعاينة إلى تحديث تلقائي** — مؤجَّلة عمداً: التوليد 1495 مللي، فالتلقائية تعني ~3.5 ثانية بعد كل توقّف عن الكتابة. تُراجَع إن نزل الزمن دون ~400 مللي.

### ⚪ لاحقة
- مراقبة مجلد مخرجات السكنر.
- تقارير ولوحات متقدمة.
- نسخة ويب/هاتف (اطلاع + اعتماد + مسح QR بالكاميرا).

### مؤجَّلات صغيرة من وحدتَي الوارد والأقسام
- ربط الصادر بالوارد **أثناء إنشاء الصادر** (حالياً من شاشة الوارد فقط).
- **نظام إشعارات كامل** (مقروء/غير مقروء) — حالياً يكفي ظهور الكتاب في قائمة الموظف + شارة الشريط العلوي (ADR-015).
- توسيع الأقسام لتشمل **الصادر** (حالياً للوارد فقط، لأن دورة الصادر اعتماد لا إحالة).

> ✅ **حُلَّ 2026-07-25:** «الإحالة نصّ حر لا يراه موظفو القسم» — صارت إسناداً حقيقياً لقسم، والموظف يرى كتب قسمه ([ADR-015](decisions.md)).

## 7) تشغيل النظام

```bash
# الخادم (نافذة أولى) — المنفذ 5080 ثابت
cd D:\DMS\backend
dotnet run --project Dms.Api

# الواجهة (نافذة ثانية)
cd D:\DMS\app
flutter run -d chrome
```

- **قاعدة البيانات:** SQL Server المثيل الافتراضي (`Server=.`)، قاعدة `DmsDb`.
  ⚠️ أدوات `dotnet ef` تقرأ `appsettings.json` (إعدادات الإنتاج) فتفشل بخطأ TCP — للفحص السريع استخدم:
  `sqlcmd -S . -E -d DmsDb -I -Q "..."` (الخيار `-I` ضروري مع الجداول ذات الفهارس المفلترة).
- **الأسرار:** `backend/Dms.Api/appsettings.Development.json` (غير مُدرج في git).
- **أوقف الـ API قبل إعادة البناء** — يقفل ملفات الإخراج.

### اختبارات التدفق الشامل (E2E) — أربعة سكربتات، 127 تحقّقاً

| السكربت | التحقّقات | يغطّي |

## 9) ⚠️ عمل قيد التنفيذ — لم يصل `main` بعد (2026-07-27)

> **هذا القسم يُحذف فور اكتمال الدمج.** وُجد لأن المالك اختبر إصلاحاً لم يكن قد وصل إليه،
> فأمضى وقتاً يختبر كوداً قديماً — ولا يصحّ أن يتكرّر.

**حالة `main` = `370efbb`** — سليم ويعمل. يحوي: إصلاح 404 بعد الإحالة · صلاحية مرفقات الوارد ·
أول دخول · **محرّك pdf.js مستضاف محلياً**.

| العمل | الحالة | لماذا لم يُدمج |
|---|---|---|
| **إصلاح زر العين (`?inline=true`)** | ✅ الكود جاهز ويبني | حُبس مع الإحالة المتعددة في نفس الفرع — **خطأ ترتيب، كان يجب فصله** |
| **الإحالة المتعددة (ADR-018)** | 🟡 الباك-إند مكتمل ويبني · **الواجهة ناقصة ولا تبني** | ميزة نصف مبنية |

### ما أُنجز فعلياً من الإحالة المتعددة
كيان `IncomingAssignment` (كتاب ↔ عدة أقسام، لكل إسناد ملاحظته ومَن أحاله ومتى) ·
`ForwardAsync` تراكمية تقبل عدة أقسام + ملاحظة عامة وتُنشئ سطر سجلّ لكل قسم ·
قاعدة الرؤية والفلترة وحذف القسم صارت «أي إسناد» · migration `AddMultiDepartmentAssignments`
(بترتيب صحيح: إنشاء ← نقل ← إسقاط) · حذف `FolderName` نهائياً · نماذج Flutter.

**المتبقّي:** شاشة الإحالة الجديدة · إصلاح شاشات تقرأ `departmentName` المحذوف · تصفير الوارد ·
حارس E2E · ADR-018 نهائي.

### 🔴 حادثة يجب ألّا تتكرّر: مهاجرة من فرع على قاعدة مشتركة
طُبّقت مهاجرة الإحالة المتعددة على `DmsDb` بينما المالك يُشغّل الخادم من `main`. المهاجرة تحذف
`IncomingBooks.DepartmentId`، فصار **المخطّط متقدّماً على الكود** ⇒ كل استعلام وارد يفشل بـ
`Invalid column name 'DepartmentId'`، وتوقّف النظام عن العمل حتى أُرجعت المهاجرة.

> **قاعدة مُلزِمة:** قاعدة البيانات **مورد مشترك** بين `main` والـworktrees.
> **لا تُطبَّق أي مهاجرة على `DmsDb` قبل دمج كودها في `main`.** وللتجريب: قاعدة منفصلة.
