# قواعد: سير العمل والتوثيق المستمر

## اقرأ أولاً في كل جلسة
**[`../docs/status-report.md`](../docs/status-report.md)** — المرجع الحيّ لحالة المشروع: أين وصلنا، ما المكتمل، ما الفجوات المفتوحة، وما التالي. لا تبدأ عملاً قبل قراءته.

## التوثيق المستمر (إلزامي)
بعد كل **خطوة مهمة** (ميزة جديدة، قرار تقني، إصلاح جوهري، أو إكمال مهمة):
0. **حدّث [`../docs/status-report.md`](../docs/status-report.md)** — جدول الرأس (آخر تحديث/آخر إنجاز/الحالة/المرحلة القادمة) + حالة الوحدة + الفجوات + ما تبقّى. **هذا الملف يجب ألّا يتقادم أبداً.** لا تُسجّل فيه إنجازاً لم يُختبر ولا تُخفِ فجوة معروفة.
1. أضِف سطراً في [`../docs/progress-log.md`](../docs/progress-log.md) بالتاريخ ووصف موجز.
2. إن تغيّرت المعمارية → حدّث [`../docs/architecture.md`](../docs/architecture.md).
3. إن تغيّر نموذج البيانات/كيان/migration → حدّث [`../docs/data-model.md`](../docs/data-model.md).
4. إن تغيّرت نقاط النهاية → حدّث [`../docs/api-reference.md`](../docs/api-reference.md).
5. إن اتُّخذ قرار تقني → أضِف ADR في [`../docs/decisions.md`](../docs/decisions.md).
6. حدّث حالة المراحل في [`../docs/roadmap.md`](../docs/roadmap.md).
7. عند تغيّر تقنية/أمر تشغيل → حدّث [`../CLAUDE.md`](../CLAUDE.md) والمهارات في `../skills/`.

> الهدف: التوثيق يبقى مطابقاً للواقع دائماً (لا يتقادم).

## البناء والاختبار
- ابنِ بعد كل تغيير جوهري؛ لا تُكمل مع أخطاء بناء.
- شغّل اختبار التدفق E2E بعد تغييرات الباك-إند المهمّة (انظر مهارة `verify-backend`).
- أوقِف الـ API قبل إعادة البناء (يقفل ملفات الإخراج).

## Migrations
- لكل تغيير في الكيانات: أنشئ migration بوصف واضح + طبّقه. لا تعدّل migration مطبّقاً.
- **رتّب عمليات المهاجرة يدوياً عند نقل عمود:** إنشاء ← **نقل البيانات** ← إسقاط. سقالة EF
  تُسقط أولاً فتمحو البيانات (حدث في ADR-017 وADR-018 معاً).
- 🔴 **قاعدة البيانات مورد مشترك بين `main` والـworktrees.** لا تُطبَّق مهاجرة على `DmsDb`
  قبل **دمج كودها في `main`** — وإلا صار المخطّط متقدّماً على الكود الذي يشغّله المالك
  فتعطّل النظام بـ`Invalid column name`. للتجريب: قاعدة منفصلة.

## الدمج
- **افصل الإصلاحات المستقلّة في commits مستقلّة وادمجها فوراً.** حبسُ إصلاح جاهز داخل فرع
  فيه ميزة غير مكتملة يجعل المالك يختبر كوداً قديماً ويظنّ الإصلاح فاشلاً.

## Git
- لا تنفّذ commit/push إلا بطلب صريح من المالك.
- لا تُدرج الأسرار (`appsettings.Development.json`) أو الإخراج (`App_Data/`, `output/`, `bin/`, `obj/`).

## المهام
- استخدم قائمة المهام لتتبّع العمل متعدد الخطوات؛ حدّث الحالة فور البدء/الإكمال.
