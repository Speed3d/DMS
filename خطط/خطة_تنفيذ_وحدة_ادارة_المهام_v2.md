## 0) ما تغيّر عن الإصدار 1 — وخلاصة سريعة

الإصدار 1 كان **سليم المعمارية** لكنه بُني على قراءة التوثيق لا على قراءة الكود، فوقع في
٥ اصطدامات واقعية و١٤ ثغرة تصميمية. هذا الإصدار:

| البند | الإصدار 1 | الإصدار 2 |
|---|---|---|
| الدفعات | 5 | **7** (فُصلت الحزم المتلاصقة، وأُضيفت دفعة الصلاحيات) |
| اسم حالة المهمة | `TaskStatus` ⇒ **يكسر البناء** | `DmsTaskStatus` |
| `OwnerType.Task` | `4` ⇒ **يصطدم بـ`PayrollPeriod`** | `6` |
| أرقام الـADR | 029/030/031 ⇒ **029 مأخوذ** | **030 / 031 / 032** |
| سلسلة `CanManageTasks` | ملف واحد | **٩ ملفات باك-إند + ٢ واجهة** |
| اختبارات الخدمة | ~17 اختبار وحدة | **مُلغاة بقرارٍ مُعلَّل** ⇐ E2E |
| الخدمات الخلفية | فقرتان وصفيّتان | **تصميم كامل**: حالة دائمة · حارس صيانة · تجميع بالشركة · حارس تكرار |
| «متأخر» | `DueDate < UtcNow` | **يوم لا لحظة**، بتوقيت بغداد |
| الملفات | ~30 جديد + 25 معدَّل | **~34 جديد + ~38 معدَّل** |

**قرارات المالك الأربعة الجديدة (2026-08-10) مُدمَجة كلها:**
المدير في التصعيد = **كل مدير في الشركة** · **القارئ لا يرى المهام** ·
الكانبان **صفحة مستقلّة وغير مؤجَّل** · **الخدمات الخلفية ضمن الخطة، لا إطلاق ناقص**.

## 2) قرارات اتخذتُها نيابةً عنك — **راجعها**

هذه ليست تفاصيل تنفيذ؛ كلٌّ منها يغيّر سلوكاً يراه المستخدم. حسمتُها لئلا تتعطّل الخطة،
**وكلٌّ قابل للنقض بكلمة**.

| # | القرار | البديل المرفوض | لماذا |
|---|---|---|---|
| **D1** | **«الموعد يومٌ لا لحظة»** — المهمة تتأخّر بعد **نهاية يومها بتوقيت بغداد (+03:00 ثابتاً)**. مهمة موعدها اليوم **ليست متأخرة اليوم** | `DueDate < UtcNow` (الإصدار 1) | يجعل مهمة موعدها 15 آب «متأخرة» الساعة 3:00 فجراً من يوم 15 نفسه. والعراق بلا توقيت صيفي منذ 2015 فالإزاحة الثابتة أدقّ من قاعدة مناطق زمنية قد تغيب عن الجهاز |
| **D2** | **إشعار واحد لكل (مهمة × مستوى تصعيد)** — لا تذكير يومياً متكرراً | «إن لم يُرسل اليوم» (الإصدار 1) | مهمة متأخرة أسبوعين × ٥ مديرين = 70 إشعاراً بلا معلومة جديدة. التصعيد يقول «ساءت الحال» — والحال لا تسوء كل يوم. ⚠️ **إن أردتَ التذكير اليومي فهو سطران** (`LastEscalatedAt.Date < today`) والعمودان موجودان أصلاً |
| **D3** | **التكرار = «مهمة أمّ» + نُسَخ** — الأمّ وحدها `IsRecurring=true`، والنُسَخ عاديّة مربوطة بها. وحارسٌ **مضاعف**: فحصُ وجودٍ قبل الإنشاء **+ فهرس فريد** `(ParentRecurringTaskId, DueDate)` | نسخة متكررة تُنجب متكررة | بدونه: كل نسخة تُنجب، والخدمة تعمل **كل ساعة** ⇒ تكاثرٌ أُسّي |
| **D4** | **المدير فأعلى يرى كل مهام الشركة** | «مهامه + قسمه + ما أنشأ» (الإصدار 1) | اتساقاً مع الصادر والوارد (`rules/security.md`): المدير يرى كل كتب شركته. وقاعدةُ رؤيةٍ ثالثة مختلفة تُنسى وتتباعد |
| **D5** | **`Notification` بحذفٍ فعليّ لا ناعم** + تنظيف تلقائي بعد **90 يوماً** | الحذف الناعم دائماً (`rules/security.md`) | **استثناء صريح موثَّق**: الإشعار **إخطارٌ بحدث** لا سجلّ الحدث؛ السجلّ في `TaskUpdate` و`AuditLog` وكلاهما باقٍ. وبقاؤها يعني نموّاً بلا سقف على قرص السيرفر الداخلي |
| **D6** | **تعميم `RequireHrModuleAttribute` ⟵ `RequireGrantedModuleAttribute`** (قسمٌ يُمنح صراحةً ولا يناله القارئ) وتشمل الموظفين والرواتب **والمهام** | نسخة ثالثة من الحارس نفسه | ثلاث نسخ من حارس أمنيّ = ثلاثة أماكن تُنسى. ⚠️ **إعادة تسمية ميكانيكية تمسّ ٣ controllers قائمة** — وحارسُ الانحدار جاهز: `hr-e2e.ps1` بـ**151 تحقّقاً** يُشغَّل بعدها إلزاماً |
| **D7** | **المربّعات الحسّاسة تبدأ مُطفأة في شاشة المستخدمين** — `_ensureAccess` يبدأ بـ`kDefaultModules` (السبعة الأساسية) لا `kAllModules` | إبقاء الحال | 🔴 **عيبٌ قائم اكتشفته أثناء الفحص**: [users_screen.dart:543](../app/lib/screens/users_screen.dart:543) يُهيّئ أي إسناد جديد بـ`kAllModules` — **فالموظفون والرواتب مُؤشَّران افتراضياً** رغم أن `AppModule.All = 127` استُثنيا منها عمداً. إضافة `Tasks` بلا هذا التصحيح تكرّر العيب ثالثةً |
| **D8** | **جرسان لا ثلاثة** — زرّ «مسودّات بانتظار الاعتماد» القائم يتحوّل أيقونته إلى `pending_actions`، والجرس `notifications` يبقى **للإشعارات وحدها** | ثلاث أيقونات إشعار متجاورة | [topbar.dart:224](../app/lib/widgets/topbar.dart:224) يستعمل `notifications_none` لقائمة مسودّات — وهي **قائمة عمل** لا إشعار. تغييرُ أيقونةٍ واحدة يزيل الالتباس |
| **D9** | **لا اختبارات وحدة للخدمات** — تغطيتها بـE2E على SQL Server حقيقي | `TaskServiceTests` (~12) + `NotificationServiceTests` (~5) | `Dms.Tests` يرجع `Dms.Domain` و`Dms.Documents` **فقط**، وكل الـ**217** اختباراً منطق مجال نقيّ. وبناء بيئة اختبار خدمات هنا **يعطي ثقةً كاذبة**: مزوّد Sqlite **لا يدعم `IsRowVersion`** (وهو محور التزامن المتفائل)، ومزوّد InMemory **لا يدعم `FromSql`** (وهو محور `NumberingService`) ولا المعاملات. ⇒ المنطق القابل للعزل يُنقَل إلى **دوالّ نقيّة** تُختبَر بالوحدة، والباقي إلى E2E — وهو **نهج المشروع المُثبَت** (**325** تحقّقاً في ستة سكربتات) |
| **D10** | **الشارات تُحدَّث باستقصاء كل 60 ثانية** | SignalR / WebSocket | لا SignalR في المشروع، وإدخاله لأجل شارة = طبقةُ نقلٍ جديدة على سيرفر داخلي. والاستقصاء يُوقَف عند تسجيل الخروج وعند غياب القسم |

# الدفعة 1 — طبقة المجال والمهاجرة

## 1.1 `[NEW] backend/Dms.Domain/DmsTask.cs`

```csharp
namespace Dms.Domain;

/// <summary>مهمة — وحدة عملٍ مُسنَدة لموظف أو لقسم، لها موعدٌ وحالةٌ وتقدّم.</summary>
/// <remarks>
/// ⚠️ الاسم `DmsTask` لا `Task`: `System.Threading.Tasks.Task` مستوردٌ عالمياً
/// (`ImplicitUsings`) في المشاريع الثلاثة. والقاعدة نفسها تسري على **كل** أنواع هذه الوحدة.
/// </remarks>
public class DmsTask
{
    // ── المعرّف والترقيم ──
    public int TaskId { get; set; }
    public int CompanyId { get; set; }
    public string? TaskNumber { get; set; }        // DEN-TSK-2026-00001
    public int? Year { get; set; }
    public int? SerialNo { get; set; }

    // ── المحتوى ──
    public string Title { get; set; } = "";        // max 500
    public string? Description { get; set; }       // نصّ حرّ — ليست وثيقة فلا HTML

    // ── التصنيف ──
    public DmsTaskType TaskType { get; set; }
    public DmsTaskPriority Priority { get; set; }
    public DmsTaskStatus Status { get; set; }

    public int ProgressPercent { get; set; }       // 0..100

    // ── المواعيد ──
    /// <summary>**يومُ الاستحقاق** لا لحظتُه — يُخزَّن عند 00:00 ويُقاس بيومه كاملاً (D1).</summary>
    public DateTime DueDate { get; set; }
    public DateTime? StartDate { get; set; }
    public DateTime? CompletedDate { get; set; }

    // ── الإسناد ──
    public int? DepartmentId { get; set; }
    public int? AssignedToUserId { get; set; }
    public int CreatedByUserId { get; set; }

    // ── الربط بالوثائق ──
    public int? RelatedIncomingId { get; set; }
    public int? RelatedOutgoingId { get; set; }

    // ── التكرار (D3) ──
    /// <summary>**الأمّ وحدها** تحمل `true`؛ النُسَخ المولَّدة عاديّة.</summary>
    public bool IsRecurring { get; set; }
    public DmsRecurrencePattern? RecurrencePattern { get; set; }
    public int? RecurrenceInterval { get; set; }
    public DateTime? RecurrenceEndDate { get; set; }
    public int? ParentRecurringTaskId { get; set; }

    // ── حالة التصعيد (B2) — تُكتب من الخدمة الخلفية وحدها ──
    /// <summary>آخر مستوى تصعيدٍ أُرسل (0 = لا شيء · 1 مسؤول · 2 مديرون · 3 رئاسة).</summary>
    public int LastEscalationLevel { get; set; }
    public DateTime? LastEscalatedAt { get; set; }
    /// <summary>تاريخ إرسال تذكير «يقترب موعدها» — يمنع تكراره.</summary>
    public DateTime? DueSoonNotifiedAt { get; set; }

    public string? Notes { get; set; }

    // ── بنية تحتية ──
    public byte[]? RowVersion { get; set; }        // ⚠️ `byte[]?` كسابقة OutgoingBook/PayrollPeriod
    public bool IsDeleted { get; set; }
    public int? DeletedByUserId { get; set; }
    public DateTime? DeletedAt { get; set; }
    public DateTime CreatedAt { get; set; }
    public DateTime? UpdatedAt { get; set; }

    // ── تنقّل ──
    public Company Company { get; set; } = null!;
    public Department? Department { get; set; }
    public User? AssignedToUser { get; set; }
    public User CreatedByUser { get; set; } = null!;
    public IncomingBook? RelatedIncoming { get; set; }
    public OutgoingBook? RelatedOutgoing { get; set; }
    public DmsTask? ParentRecurringTask { get; set; }
    public ICollection<DmsTaskUpdate> Updates { get; set; } = [];
    public ICollection<DmsTask> RecurringInstances { get; set; } = [];
}
```

> **`RowVersion` نوعُه `byte[]?`** لا `byte[] = []` — مطابقةً لـ`OutgoingBook.RowVersion`
> و`PayrollPeriod.RowVersion`. وفي **عقد الـAPI يُمرَّر نصّاً** (base64) كما فرضته العطلة
> الثانية في وحدة الرواتب (`"AAAAAAABftE="` ليست `Iterable`).

```csharp
/// <summary>حساب موعد النسخة التالية من مهمة متكررة — **دالّة نقيّة**، لا DB ولا وقت نظام.</summary>
public static class TaskRecurrence
{
    /// <summary>الموعد التالي، أو null إن تجاوز نهاية التكرار.</summary>
    public static DateTime? NextDueDate(
        DateTime currentDue, DmsRecurrencePattern pattern, int interval, DateTime? endDate)
    {
        if (interval < 1) interval = 1;
        var next = pattern switch
        {
            DmsRecurrencePattern.Daily   => currentDue.AddDays(interval),
            DmsRecurrencePattern.Weekly  => currentDue.AddDays(7 * interval),
            DmsRecurrencePattern.Monthly => currentDue.AddMonths(interval),
            _ => currentDue.AddDays(interval),
        };
        return endDate is { } e && next.Date > e.Date ? null : next;
    }
}
```

```csharp
}
```

## 6.2 `[NEW] TaskBackgroundService.cs` — خدمة **واحدة** لا اثنتان

```

│
├─ 0. if (maintenance.IsActive) → تخطَّ الدورة كلها            [X4]
│
├─ 1. التصعيد
│   └─ foreach (شركة in المهام النشطة المتأخرة GroupBy CompanyId)   [X1]
│       └─ foreach (مهمة)
│           ├─ level = DaysOverdue >= 7 ? 3 : DaysOverdue >= 3 ? 2 : 1
│           ├─ if (level <= task.LastEscalationLevel) → تخطَّ        [X2, D2]
│           ├─ المستلِمون: 1 ⇒ المسؤول أو موظفو القسم
│           │              2 ⇒ كل مديري الشركة              [Q13]
│           │              3 ⇒ رئيس الشركة (وإلا السوبر أدمن)
│           ├─ SendManyAsync(..., dedupKey: $"task:{id}:esc:{level}")
│           └─ task.LastEscalationLevel = level; task.LastEscalatedAt = UtcNow
│
├─ 2. تذكير «يقترب موعده»
│   └─ المهام النشطة التي DueDate == غداً (بتوقيت بغداد) و DueSoonNotifiedAt == null
│       └─ إشعار High + ضبط DueSoonNotifiedAt
│
├─ 3. توليد النسخة التالية للمتكررة
│   └─ foreach (مهمة انتهت (Completed/Cancelled) ولها سلسلة تكرار)
│       ├─ head = ParentRecurringTask ?? self
│       ├─ next = TaskRecurrence.NextDueDate(task.DueDate, head.Pattern, head.Interval, head.EndDate)
│       ├─ if (next == null) → انتهت السلسلة
│       ├─ if (يوجد مهمة بـ ParentRecurringTaskId == head.Id && DueDate == next) → تخطَّ  [X3]
│       ├─ أنشئ نسخة: نفس العنوان/الوصف/الأولوية/الإسناد/القسم · IsRecurring = false
```

# قواعد الدمج والنشر

1. **فرع عمل منفصل** — لا يُدمج حتى تكتمل الدفعات السبع وتُختبر.
2. **قاعدة `DmsTaskScratch` المنفصلة** للتجريب — 🔴 **لا `DmsDb` أبداً**.
   ⚠️ `dotnet run` **يتجاهل `ASPNETCORE_URLS`** لصالح `launchSettings.json`، و**الـAPI
   يهاجر تلقائياً عند الإقلاع** (`DbSeeder`) ⇒ **تشغيلُ الخادم بقاعدةٍ خطأ = تطبيقُ مهاجرة
   بلا قصد**. تُمرَّر بـ`ConnectionStrings__Default`.
3. **نسخة احتياطية لـ`DmsDb`** قبل الدمج · ويُتحقَّق منها من **`msdb.dbo.backupset`** لا من
   نظام الملفات (`Test-Path` يفشل بـAccess denied — الكتابة بحساب الخدمة).
   ⚠️ `WITH COMPRESSION` **غير مدعوم على SQL Server Express**.
4. **الدمج في `main` ⟵ ثمّ تطبيق المهاجرتين** بـ`sqlcmd -b`.
   > 🔴 **القاعدة مورد مشترك** بين `main` والـworktrees **والخادم الذي تشغّله**. مخطَّطٌ
   > متقدّمٌ على الكود يعطّل النظام بـ`Invalid column name`.
5. **تحقّق حيّ بعد التطبيق:** الجدولان + العمود · المهاجرتان في `__EFMigrationsHistory` ·
   **والبيانات القائمة سليمة** (المستخدمون · الشركات · الصادر · الوارد · الأرشيف · الموظفون
   · الرواتب) · و**الوحدات العشر تعمل**.
6. **إيقاف الـAPI قبل إعادة البناء** — يقفل ملفات الإخراج.
