تعديلات بعد المراجعة التقنية (2026-06-28):
- **محرّك PDF:** اعتماد **QuestPDF** (مكتبة .NET أصلية، بلا متصفح) بدل PuppeteerSharp/Playwright — لتفادي فشل Chromium على Azure App Service ولاستقلالية الاستضافة.

- **إضافات للخطة:** استراتيجية اختبارات، بدء تشغيل (Bootstrap)، مصادقة دون اتصال + حلّ تعارض المزامنة، مراقبة الإنتاج (App Insights)، واختيار منطقة Azure.

## 1) نظرة عامة والأهداف

نظام إدارة وثائق إلكتروني يعمل عبر الإنترنت على **استضافة سحابية مركزية**، يُثبَّت كتطبيق سطح مكتب على أجهزة المستخدمين، ويتصل الجميع بقاعدة بيانات **مركزية واحدة** (مصدر بيانات وحيد، بلا مزامنة يدوية).

**الأهداف:**
- إنشاء وإدارة **الكتب الصادرة** بترويسة الشركة وتوليدها PDF جاهزة للطباعة.
- **أرشفة** المستندات والملفات وإرفاقها والبحث فيها.
- **قوالب متعددة ومتعددة الشركات** قابلة للتعديل دون تعديل الكود.
- **متابعة مالية** (مبالغ بالدينار/الدولار) وتقارير مالية بالدينار العراقي.
- **QR بتوقيع رقمي غير قابل للتزوير** للاسترجاع والتحقق.
- **تسلسل صلاحيات هرمي**، **سجل تدقيق**، **سجل إصدارات**، **نسخ احتياطي**، و**تقارير**.

**مبدأ التصميم:** بساطة، سلاسة، دقة، كفاءة عالية — بلا تعقيد غير ضروري.

## 2) المصطلحات (Glossary)

| المصطلح | المعنى |
|---|---|
| الصادر | الكتب التي تُنشئها الشركة وتُرسلها لجهات خارجية. |
| الأرشيف | المستندات/الملفات التي تُحفظ ويُبحث فيها. |
| القالب (Template) | تصميم الكتاب لكل شركة: صورة هيدر + صورة فوتر + علامة مائية + منطقة متن. |
| المسودّة (Draft) | كتاب قيد الإعداد، قابل للتعديل، بلا رقم رسمي. |
| الاعتماد (Approval) | إقرار الكتاب نهائياً وإصدار رقمه الرسمي وتوليد PDF + QR موقّع. |
| سجل الإصدارات (Versioning) | حفظ نسخة من الكتاب عند كل تعديل بعد الاعتماد. |
| التوقيع الرقمي للـ QR | توقيع مشفّر داخل الـ QR يمنع تزويره. |
| Super Admin | أعلى صلاحية تقنية/نظامية (المطوّر/المالك التقني). |
| رئيس الشركة | أعلى صلاحية إدارية في الشركة. |

## 6) الاستضافة والتكلفة

**المعتمد: Azure (مُدار، بلا صيانة سيرفر).**

| المكوّن | الخدمة | التكلفة التقديرية |
|---|---|---|
| تشغيل الـ API | Azure App Service (Basic) | ~13 دولار/شهر |
| قاعدة البيانات | Azure SQL (Basic/Serverless) | ~5–15 دولار/شهر |
| التخزين | **Azure Blob Storage** (حصرياً) | بضع دولارات |
| إدارة المفاتيح | Azure Key Vault | بضعة سنتات |
| دومين | اسم نطاق | ~12–15 دولار/سنة |
| **الإجمالي** | | **~25–35 دولار/شهر تقريباً** |

**المنطقة:** اختيار الأقرب للعراق (مثل **UAE North** أو **West Europe**) لتقليل زمن الاستجابة ومراعاة سيادة البيانات.
**نظام التشغيل:** بما أن QuestPDF أصلية بلا متصفح، **لا قيد على Windows/Linux App Service** — يُختار الأرخص/الأنسب.
**تخزين الملفات:** لا يُستخدم القرص المحلي لـ App Service إطلاقاً (يُفقد عند Scale-out/إعادة النشر) — كل الملفات على **Blob Storage**.
**بديل أوفر (نفس الكود): VPS صغير** ~5–10 دولار/شهر (الكود مستقل عن الاستضافة).
**حجم البيانات:** ~400 كتاب/سنة × 5 ميغا ≈ 2 غيغا/سنة → السعة مريحة لسنوات.
**OneDrive (نسخ احتياطي):** الرفع التلقائي يتطلب **Microsoft Graph + تسجيل تطبيق + صلاحيات** (يُفضّل OneDrive for Business). كبديل أبسط: **تصدير bacpac من Azure SQL + نسخ Blob** إلى حساب تخزين/أرشيف.

## 7) المستخدمون والأدوار والصلاحيات (تسلسل هرمي)

### التسلسل
```
سوبر أدمن (أنت)  ←  رئيس الشركة  ←  مدير  ←  موظف  ←  قارئ
  تقني/نظامي        أعلى دور إداري    يدير      مسودّات   مشاهدة
  + نسخ احتياطي     ينشئ مدراء وموظفين  الموظفين   وعمله فقط
```
**القاعدة الذهبية:** كل مستوى يدير **المستويات الأدنى منه فقط** — لا أحد يعدّل من هو في مستواه أو أعلى.

### نموذج تعدد الشركات (Tenancy) — مختلط
- كل مستخدم مرتبط بـ **`CompanyId`** (شركته)؛ **رئيس الشركة** قد يُسنَد لأكثر من شركة.
- **عزل بياني صفّي (Row-level):** كل استعلامات الصادر/الأرشيف/التقارير/المستخدمين تُصفّى تلقائياً حسب شركة المستخدم على مستوى الباك-إند.
- **السوبر أدمن** يرى ويدير **كل الشركات**؛ **رئيس الشركة** يرى شركاته المُسندة؛ **المدير/الموظف/القارئ** مقيّدون بشركتهم فقط.
- العزل يُفرَض في الـ API (لا يُعتمد على الواجهة) لمنع تجاوز حدود الشركة.

## 8) الأنظمة الفرعية (Modules)

### 8.1 الشركات والقوالب (بالصور)
- إدارة **شركات متعددة**: اسم، رمز ترقيم (DEN…)، حالة تفعيل.
- **القالب لكل شركة يتكوّن من:**
  - **صورة الهيدر** (أعلى الصفحة) — تصميم الشركة كاملاً (لوجو + ترويسة).
  - **صورة الفوتر** (أسفل الصفحة) — العنوان/الإيميل/الهاتف.
  - **علامة مائية اختيارية** (لوجو وسط الصفحة) **بشفافية قابلة للتحكم (0–100%)** خلف النص.
  - **منطقة المتن**: تُكتب فيها الحقول المتغيّرة كنصّ حقيقي (الرقم/التاريخ/الجهة/الموضوع/النص/QR).
- المواصفات: **A4 ثابت**، صور بدقة **300 DPI**، **خط عربي مفتوح الترخيص (OFL)** (Cairo / Amiri / Noto Naskh Arabic) قابل للتضمين في PDF على السيرفر.
- المتن يبقى **نصاً حقيقياً** (قابلاً للبحث والتحديد) — الصور للهيدر/الفوتر/العلامة فقط.
- إدارة كاملة: رفع/تعديل الصور، ضبط الشفافية والهوامش، تفعيل/تعطيل — دون لمس الكود.

### 8.2 نظام الصادر
**إنشاء كتاب:** الشركة (تحدّد القالب والرمز) ← الجهة المستلمة ← الموضوع ← نص الكتاب (محرّر RTL) ← **الحقول المالية** (اختياري) ← مرفقات (اختياري).
**الحقول المالية:** المبلغ + العملة (دينار/دولار) + سعر الصرف (إلزامي للدولار) + المعادل بالدينار (يُحسب تلقائياً).
**دورة الحياة:**
```
مسودّة  →  [المدير فأعلى: اعتماد]  →  نهائي (رقم + PDF + QR موقّع، مقفل)
                                          │
                          تعديل/حذف ناعم (مدير فأعلى) → سجل إصدار + إعادة توليد PDF/QR
```
**الناتج:** PDF جاهز للطباعة + تصدير Word.

### 8.3 نظام الأرشيف
**إضافة مستند:** رقم أرشيف تلقائي، العنوان، رقم الكتاب، تاريخه، الجهة الصادرة/المستلمة، النوع، **الحقول المالية** (نفس منطق الصادر)، الكلمات المفتاحية، الملاحظات + **المرفقات** (PDF/JPG/PNG/Word/Excel — سحب وإفلات، متعدد، معاينة).
**البحث:** رقم الكتاب، التاريخ، **فترة زمنية**، الجهة، النوع، الكلمات المفتاحية، اسم الملف، الباركود/QR.

### 8.4 الباركود / QR (غير قابل للتزوير)
- يُولَّد عند الاعتماد ويُطبع على الكتاب.
- يحتوي على رمز الكتاب + بيانات مفتاحية + **توقيع رقمي غير متماثل (ECDSA P-256)** يُولَّد بمفتاح خاص محفوظ في **Azure Key Vault** لدى السيرفر فقط (توقيع صغير يناسب سعة QR).
- **التحقق على مستويين:**
  1. **التوقيع الرقمي:** أي تعديل في محتوى الـ QR يُبطل التوقيع → كشف فوري للتزوير (يعمل حتى دون اتصال).
  2. **قاعدة البيانات:** يفتح السجل الرسمي (الرقم/التاريخ/الجهة/الموضوع/المبلغ/الحالة) لمطابقته بالورقة.
- **استرجاع:** ماسح USB أو إدخال يدوي → يفتح سجل الكتاب فوراً.

### 8.5 القوائم المُدارة (الجهات / أنواع الكتب)
- تُدخَل مرة واحدة وتُختار من قوائم منسدلة عند الإنشاء (تناسق + بحث + تقارير دقيقة).

### 8.6 البحث
- بحث موحّد عبر الحقول والكلمات المفتاحية + **بحث بفترة زمنية** (للتقارير المالية).

### 8.7 التقارير
- الصادر: يومي/شهري/سنوي/حسب الجهة/الشركة.
- الأرشيف: حسب الجهة/النوع/التاريخ.
- **التقرير المالي:** لفترة محددة → قائمة الكتب + **مجموع المبالغ بالدينار العراقي** (باستخدام المعادل المخزّن لكل كتاب)، مع تصفية حسب الشركة/الجهة.
- نشاط المستخدمين (من سجل التدقيق).
- تصدير: PDF / Excel.

### 8.8 سجل التدقيق
- تسجيل تلقائي لكل عملية (إضافة/تعديل/حذف/اعتماد) مع المستخدم والتاريخ والوقت.

### 8.9 سجل الإصدارات (Version History)
- عند تعديل كتاب **بعد اعتماده**: يُحفظ **سناب-شوت** للنسخة السابقة (ماذا تغيّر، من، متى)، ويُعاد توليد PDF/QR — مع بقاء الرقم ثابتاً.

### 8.10 النسخ الاحتياطي
- يتحكم به **السوبر أدمن فقط**: **يومي / أسبوعي / يدوي / إيقاف** + زر «نسخة الآن».
- ينسخ قاعدة البيانات + الملفات + يرفع نسخة إلى **OneDrive**.

### 8.11 التصدير والطباعة
- لكل كتاب: طباعة مباشرة، تصدير PDF / Word.

### 8.12 وضع المسودّات دون اتصال
- عند انقطاع الإنترنت: إنشاء/تعديل **المسودّات** يُحفظ **محلياً** (SQLite) في طابور مزامنة.
- عند عودة الاتصال: **مزامنة تلقائية** ترفع المسودّات للسيرفر.
- **الاعتماد وإصدار الرقم يبقيان أونلاين** (لمنع تكرار الأرقام). مؤشّر يوضّح العناصر بانتظار المزامنة.
- **المصادقة دون اتصال:** يُخزَّن آخر JWT/refresh + بصمة جلسة بأمان محلياً (مع مدّة صلاحية قصوى) للسماح بالعمل على المسودّات فقط دون اتصال؛ تنتهي الجلسة المحلية تلقائياً عند تجاوز المدّة.
- **حلّ التعارض:** لكل مسودّة `LocalId` + `UpdatedAt`؛ عند المزامنة **آخر تعديل يفوز** مع التحقق من بقاء المراجع (الشركة/القالب/الجهة)؛ إن حُذف مرجع تُعلَّم المسودّة «تحتاج مراجعة» بدل رفضها.
- **المرفقات offline:** تُحفظ محلياً وتُرفع إلى Blob عند المزامنة (لا تُخزَّن داخل SQLite).

**قواعد مهمة:**
- **توليد الرقم:** داخل Transaction بمفتاح (شركة + سنة + نوع) مع قفل صفّي (`UPDLOCK`) أو تزامن متفائل (rowversion) لمنع التكرار، تصفير سنوي. **السنة تُحدَّد لحظة الاعتماد** (لا لحظة المسودّة).
- **المعادل بالدينار:** `AmountInIqd = (Currency=USD ? Amount × ExchangeRate : Amount)` — يُجمَّد لحظة الإنشاء/الاعتماد فلا تتأثر التقارير بتغيّر السعر لاحقاً.
- **تخزين الملفات:** على **Azure Blob Storage**، ويُحفظ **مفتاح Blob فقط** في قاعدة البيانات، ويُقدَّم عبر الـ API (Stream/رابط موقّع مؤقت) مع التحقق من الصلاحية والشركة.
- **الحذف:** منطقي (`IsDeleted` + `DeletedBy/DeletedAt`) دائماً — لا حذف فعلي.
- **العزل الصفّي:** كل استعلام يُصفّى بـ `CompanyId` تلقائياً (EF Global Query Filter) حسب شركة المستخدم، عدا السوبر أدمن.
- **البحث:** إنشاء **Full-Text Index** على `Subject/BodyHtml/Keywords/Title` بـ Collation عربي مناسب على Azure SQL.

## 11) تدفقات العمل (Workflows)

**أ) كتاب صادر:** الموظف ينشئ مسودّة (شركة/جهة/موضوع/نص + مالي + مرفقات) → يحفظ → المدير فأعلى «يعتمد» → النظام يولّد الرقم + QR موقّع + PDF → طباعة → توقيع يدوي → حفظ الأصل.

**ب) تعديل بعد الاعتماد:** المدير فأعلى يفتح الكتاب → يعدّل → النظام يحفظ **إصداراً** للنسخة القديمة + يعيد توليد PDF/QR + يسجّل في التدقيق.

**ج) أرشفة:** مسح خارجي → «إضافة للأرشيف» → الحقول + المالي + الكلمات المفتاحية → إرفاق الملف → حفظ.

**د) تحقق QR:** مسح الرمز → فحص التوقيع الرقمي (كشف التزوير) → فتح السجل الرسمي → مطابقة الورقة.

**هـ) تفويض عاجل:** المدير غائب → رئيس الشركة/السوبر أدمن يمنح موظفاً تفويض اعتماد مؤقت → يعتمد الكتاب العاجل → يُسجَّل → ينتهي التفويض تلقائياً.

**و) عمل دون اتصال:** انقطاع الإنترنت → مسودّات تُحفظ محلياً → عودة الاتصال → مزامنة تلقائية → الاعتماد/الترقيم أونلاين.

## 12) قواعد العمل والتحقق (Business Rules)

- لا يُصدَر رقم رسمي إلا عند **الاعتماد** (المسودّة بلا رقم).
- الرقم **فريد** لكل (شركة + سنة) ولا يُعاد استخدامه.
- **بعد الاعتماد:** التعديل/الحذف للمدير فأعلى فقط، **مع حفظ إصدار** وإعادة توليد PDF/QR.
- **الحقول المالية:** إذا العملة **دولار** → **سعر الصرف إلزامي**؛ إذا **دينار** → المبلغ مباشرة. التقارير تجمع **بالدينار**.
- الحقول الإلزامية للصادر: الشركة، الجهة، الموضوع، النص.
- الموظف يرى/يعدّل عمله فقط؛ لا يعدّل/يحذف كتاباً معتمداً.
- كل حذف = **حذف ناعم** + تسجيل في التدقيق.
- صيغ المرفقات: PDF/JPG/PNG/DOCX/XLSX بحدّ حجم معقول.
- **التسلسل الهرمي:** كل مستخدم يدير المستويات الأدنى منه فقط.

- **اللغة:** عربي RTL كامل (+ إنجليزي في الترويسة).
- **الأداء:** زمن استجابة < ~2 ثانية للعمليات العادية.

- **التوسّع:** متعدد الشركات، يتحمّل نمو سنوات بلا إعادة بناء.

## 15) الأمان (Security)

- **JWT** (+ Refresh مع تدوير) + تجزئة كلمات المرور (BCrypt/Argon2) + **HTTPS** إلزامي.
- **Rate-limiting + قفل مؤقت** بعد محاولات دخول فاشلة (منع التخمين).
- **RBAC هرمي** + **عزل صفّي حسب الشركة** (Global Query Filter) + تصفية حسب الدور.
- **توقيع ECDSA P-256 للـ QR** + المفتاح الخاص في **Azure Key Vault** (لا في الإعدادات).
- **التحقق من المرفقات:** نوع/حجم مسموح + منع Path Traversal + ضبط Content-Type عند التقديم.
- كل وصول للملفات/البيانات **عبر الـ API فقط** (Blob لا يُكشَف مباشرةً).
- **سجل تدقيق + سجل إصدارات** كاملان للمساءلة، و**App Insights** للمراقبة.
