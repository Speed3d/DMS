## 0) اقرأ هذا أولاً

### 🔴 ثلاثة قرارات لا يمكن التراجع عنها بعد أول كتابٍ رسميّ

| القرار | لماذا لا رجعة فيه | يُضبط في |
|---|---|---|
| **اسم الدومين** | يُخبَز في **ختم QR داخل كل PDF** لحظة الاعتماد. كتابٌ اعتُمد بعنوانٍ قديم يحمله للأبد | [المرحلة أ](#2-المرحلة-أ--الدومين-أولاً) |
| **مفاتيح توقيع QR** | تغييرها **يُبطل التحقق من كل كتابٍ وُقّع سابقاً** | [المرحلة و](#7-المرحلة-و--الأسرار-والقاعدة-والخدمة) |
| **`QrSigning:PublicBaseUrl`** | نفس السبب — القيمة تُطبع في الرمز نفسه | تلقائيّ من `--origins` |

**فالدومين يُشترى قبل أي شيء آخر** — لا بعد تجهيز السيرفر. سببان صلبان:

1. **ملف أسرار الإنتاج** يُولَّد بالدومين (`--origins`)، ومنه يُشتقّ عنوان صفحة التحقق.
2. **حزمة الواجهة تُبنى بالدومين مضمَّناً فيها** (`--dart-define=API_BASE_URL=…`) — فلا يمكن
   بناؤها قبل معرفته، ولا تصحيحها إلا بإعادة بناءٍ ونشرٍ كاملين.

### الشكل النهائيّ

```
موظفوك · والجهات الخارجية (من أي مكان في العالم)
                    │
                    ▼
        https://dms.<دومينك>.com          ← عنوانٌ واحد للجميع، HTTPS تلقائي
                    │
                    ▼
        ☁️  Cloudflare   (حماية · شهادة · حجب هجمات)
                    │  نفقٌ صادرٌ مشفّر — **صفر منافذ مفتوحة على راوترك**
                    ▼
        🖥️  Mini PC في المكتب
            ├── IIS        :80    → الواجهة (ملفات ثابتة)
            ├── DMS API    :5080  → /api/*  و  /v/*   (خدمة ويندوز)
            ├── SQL Server Express → قاعدة DmsDb
            └── C:\DMS\data\       → المرفقات + النسخ الاحتياطية
```

### أين يذهب كل شيء

```
C:\DMS\
├── api\                      ← التطبيق (يُستبدل عند كل تحديث)
│   ├── Dms.Api.exe
│   ├── appsettings.Production.json   🔑 الأسرار — لا يُستبدل أبداً
│   └── ops\update-dms.ps1            ← سكربت التحديث الآمن
├── app\                      ← الواجهة (ملفات ثابتة لـIIS)
├── data\                     ← **خارج مجلد التطبيق عمداً** فلا يمسّه التحديث
│   ├── storage\              ← المرفقات وصور القوالب
│   └── backups\              ← النسخ الاحتياطية
└── releases\                 ← نقاط الرجوع (يُنشئها سكربت التحديث)
```

## 1) المشتريات

### الأجهزة

| البند | المواصفة الموصى بها | ملاحظة |
|---|---|---|
| **Mini PC** | معالج حديث (i5/Ryzen5 فأعلى) · **16 جيجا رام** · **SSD NVMe 512 جيجا** | ✅ لديك |
| **UPS** | يكفي لإطفاءٍ آمن (٥–١٠ دقائق حِمل) | ✅ لديك · **إلزامي**: انقطاعٌ مفاجئ أثناء كتابةٍ قد يُتلف القاعدة |
| **قرص خارجي** | SSD خارجي **1 تيرابايت** | للمرآة الشهرية — **يُحفظ خارج المبنى** |
| **كيبل شبكة** | Cat5e/Cat6 من الراوتر مباشرةً | 🔴 **لا واي-فاي للسيرفر** — انقطاعةٌ لحظية تُسقط النفق |

### الاشتراكات والتراخيص

| البند | التكلفة التقريبية | ملاحظة |
|---|---|---|
| **دومين `.com`** | 10–12 دولار/سنة | من Cloudflare مباشرةً · **فعّل التجديد التلقائي** |
| **Cloudflare** | **مجاني** | الخطة المجانية تكفي: نفق + شهادة + حماية |
| **ترخيص ويندوز** | حسب اختيارك ↓ | 🔴 اقرأ التنبيه أدناه |
| **Microsoft 365** (اختياري) | ~70 دولار/سنة | لنسخة OneDrive السحابية |

> ### 🔴 تنبيه الترخيص — لا تتجاوزه
> النسخة **التقييمية** من Windows Server 2022 تعمل **180 يوماً فقط**، وبعدها **يُطفئ
> الجهاز نفسه كل ساعة**. لك ثلاثة خيارات:
>
> 1. **Windows 11 Pro** (الأرخص والأبسط) — يكفي تماماً لثمانية مستخدمين، وكل خطوات هذا
>    الدليل تعمل عليه بلا تغيير عدا `Install-WindowsFeature` (يُستبدل بـ`Enable-WindowsOptionalFeature`).
> 2. **Windows Server 2022 Standard بترخيصٍ مُشترى** — الأنسب لبيئة سيرفر.
> 3. ~~التقييمية~~ — **للتجربة فقط**، لا لنظامٍ يحمل وثائق الشركة.

### أشياء تحتاجها أثناء التثبيت

- **فلاشة USB** ١٦ جيجا فأكثر · **جهاز آخر** لتحضيرها · **إنترنت** · **بطاقة دولية** للدومين
- **دفتر أو ملف مشفّر** لتدوين المفاتيح ([القائمة في §16](#مفاتيح-يجب-حفظها))

## 2) المرحلة أ — الدومين أولاً

### أ-1) حساب Cloudflare

1. `https://dash.cloudflare.com/sign-up` — بريدك + كلمة مرور قوية، وتحقّق من البريد.
2. 🔐 **فعّل المصادقة الثنائية فوراً**: اسمك (أعلى) ← **My Profile** ← **Authentication**
   ← **Two-Factor Authentication** ← Google Authenticator أو Authy.
   **هذا الحساب يتحكم بعنوان نظامك كلِّه — لا تؤجّل حمايته.**
3. **احفظ رموز الاسترداد** (Recovery Codes) في مكانٍ آمن خارج هاتفك.

### أ-2) شراء الدومين

من لوحة Cloudflare ← **Domain Registration** ← **Register Domain**:

- **اسمٌ قصيرٌ يخصّ الشركة**: مثل `denland.com` أو `ardhalarein.com`
- **`.com` فقط** — الأوسع دعماً والأقلّ مشاكل
- بعد الشراء ← ✅ **فعّل Auto-renew** — 🔴 **دومينٌ منتهٍ = نظامٌ متوقّف تماماً**

بعد الشراء يظهر الدومين في حسابك **مرتبطاً تلقائياً** بـDNS الخاص بـCloudflare.

### أ-3) اكتب عنوانك النهائيّ الآن

> **العنوان الذي سيُستعمل في كل خطوةٍ لاحقة:**
> ```
> https://dms.<دومينك>.com
> ```
> مثال: `https://dms.denland.com`
>
> ✍️ **اكتبه هنا واستعمله حرفياً في كل أمرٍ يلي — بلا `/` في آخره.**

## 3) المرحلة ب — تثبيت ويندوز

### ب-1) تحضير فلاشة الإقلاع

**من جهازك الحالي:**

1. حمّل ملف ISO (من مركز التقييم أو نسختك المرخَّصة) — اختر **Desktop Experience** لا Core.
2. حمّل **Rufus** من `https://rufus.ie`.
3. افتح Rufus ← اختر الفلاشة في **Device** ← **SELECT** واختر الـISO ← **START**.

### ب-2) الإقلاع من الفلاشة

1. وصّل الفلاشة بالـMini PC وشغّله، واضغط باستمرار **F2** أو **DEL** أو **F12** لدخول BIOS.
2. **Boot Order** ← اجعل USB أولاً ← احفظ (**F10**) واخرج.

### ب-3) التثبيت

| الشاشة | الاختيار |
|---|---|
| اللغة | **Language:** English (United States) |
| | **Time and currency:** Arabic (Iraq) ← مهمّ لصيغة التاريخ |
| | **Keyboard:** Arabic (101) |
| الإصدار | **Standard (Desktop Experience)** — 🔴 حتماً لا Core |
| نوع التثبيت | **Custom: Install Windows only (advanced)** |
| القرص | القرص الرئيسي — إن كانت عليه أقسام قديمة احذفها كلها |

سيستغرق ١٠–٢٠ دقيقة مع إعادات تشغيل تلقائية.

### ب-4) حساب المسؤول

- كلمة مرور **قوية** لحساب `Administrator`.
- 🔴 **سجّلها في مكانٍ آمن — لا يمكن استرجاعها إن نُسيت.**

### ب-5) التحديثات

**Start ← Settings ← Windows Update ← Check for updates** — ثبّت **كل** التحديثات وأعِد
التشغيل، ثم كرّر حتى لا يبقى شيء.

> ⚠️ لا تتجاوز هذه الخطوة: التحديثات تُغلق ثغراتٍ أمنية، وجهازك سيكون متاحاً من الإنترنت.

## 4) المرحلة ج — الشبكة والجهاز

### ج-1) اسم الجهاز

اضغط **Start** واكتب `sysdm.cpl` ← **Change** ← **Computer name:** `DMS-SERVER` ← أعِد التشغيل.

### ج-2) IP ثابت (حجزٌ في الراوتر)

> ⚠️ **لا تتجاوز هذه**: إن أُعيد تشغيل الراوتر وتغيّر IP السيرفر، انقطع وصولك الإداريّ إليه.

**اعرف عنوان MAC للـMini PC** — في PowerShell كمسؤول:
```powershell
Get-NetAdapter | Where-Object Status -eq 'Up' | Select-Object Name, MacAddress, LinkSpeed
```

ثم من إعدادات راوترك (عادةً `192.168.1.1`) ← **DHCP** ← **DHCP Reservation** — أضف عنوان
MAC واحجز له `192.168.1.100`.

**تأكّد بعد إعادة التشغيل:**
```powershell
Get-NetIPAddress -AddressFamily IPv4 | Where-Object InterfaceAlias -notlike '*Loopback*' | Select-Object IPAddress, InterfaceAlias
```

### ج-3) المنطقة الزمنية

> 🔴 **حرجة**: كل تاريخٍ في النظام — الكتب وسجلّ التدقيق والرواتب — يُبنى على ساعة السيرفر.

```powershell
Set-TimeZone -Id "Arabic Standard Time"
Get-TimeZone
w32tm /resync
```
يجب أن تقرأ: **`(UTC+03:00) Baghdad`**

> ⚠️ **`Arabic Standard Time` هي بغداد** — و`Arab Standard Time` (بلا «ic») هي الرياض.
> الفرق حرفان والنتيجة توقيتٌ خاطئ في كل سطر.

### ج-4) منع إعادة التشغيل أثناء الدوام

**Settings ← Windows Update ← Advanced options ← Active hours** — حدّد **7ص – 7م**.

### ج-5) تشفير القرص (BitLocker)

> **لماذا؟** لو سُرق الجهاز، لا يستطيع أحدٌ قراءة قاعدة البيانات ولا **مفاتيح التوقيع**.

⚠️ **على Windows Server يجب تثبيت الميزة أولاً** (على Windows 11 Pro تجاوز هذا السطر):
```powershell
Install-WindowsFeature BitLocker -IncludeAllSubFeature -IncludeManagementTools -Restart
```

بعد إعادة التشغيل: **Control Panel ← BitLocker Drive Encryption** ← **Turn on BitLocker**
على `C:`:

- احفظ **مفتاح الاسترداد** على **فلاشة أو ملفّ خارج الجهاز** — 🔴 بلا هذا المفتاح لن تفتح
  القرص إن تعطّل اللوح الأمّ.
- اختر **Encrypt entire drive** ← **Start encrypting**.
- كرّر لأي قرصٍ آخر يحمل بيانات.

> ⚠️ إن لم يكن في الجهاز **TPM**، ستطلب منك ويندوز تفعيل خيار «BitLocker بلا TPM» من
> `gpedit.msc` — والأسهل تفعيل TPM من BIOS إن كان موجوداً ومعطّلاً.

### ج-6) سطح المكتب البعيد

```powershell
Set-ItemProperty -Path 'HKLM:\System\CurrentControlSet\Control\Terminal Server' -Name "fDenyTSConnections" -Value 0
Enable-NetFirewallRule -DisplayGroup "Remote Desktop"
```

**للاستعمال:** من جهازك افتح `mstsc` واكتب `192.168.1.100`.

> ⚠️ **من داخل المكتب فقط.** لا تفتح RDP على الإنترنت أبداً — فهو الهدف الأول لهجمات
> التخمين. للوصول من الخارج: [Cloudflare Access](#ز-6-اختياري--حماية-إضافية) أو اذهب للمكتب.

### ج-7) UPS

1. وصّل UPS بالكهرباء، والـMini PC بـUPS (مخرج **Battery Backup** لا **Surge Only**).
2. وصّل كيبل USB بين UPS والجهاز، وثبّت برنامجه (PowerChute أو ما يرافقه).
3. اضبطه على **إطفاءٍ آمن** بعد ٥ دقائق من الانقطاع.

## 5) المرحلة د — البرامج الأساسية

### د-1) SQL Server Express

**لماذا Express؟** مجاني، وحدّه **10 جيجا للقاعدة** — يكفي مئات آلاف الكتب (المرفقات
تُخزَّن كملفات على القرص لا في القاعدة).

1. `https://www.microsoft.com/en-us/sql-server/sql-server-downloads` ← **SQL Server 2022 Express**
2. شغّل الملف ← اختر **Basic** ← اقبل الترخيص ← أكمل.
3. 📝 **دوّن اسم المثيل** الظاهر في نهاية التثبيت — عادةً **`SQLEXPRESS`**.

**ثبّت SSMS** (أداة إدارة القاعدة): اضغط **Install SSMS** في نهاية التثبيت، أو من
`https://aka.ms/ssmsfullsetup`.

> ⚠️ **لا حاجة لتفعيل TCP/IP ولا للمنفذ 1433** — التطبيق على **الجهاز نفسه** ويتصل عبر
> الذاكرة المشتركة. وفتحُ TCP بلا داعٍ يوسّع سطح الهجوم. (النسخة السابقة من الدليل طلبته.)

**تحقّق أن الخدمة تعمل:**
```powershell
Get-Service 'MSSQL$SQLEXPRESS'
```

### د-2) .NET 9 Runtime

1. `https://dotnet.microsoft.com/download/dotnet/9.0`
2. من قسم **.NET Runtime** اختر **ASP.NET Core Runtime 9.x.x** ← **Windows x64 Installer**.
3. ثبّته.

**تحقّق:**
```powershell
dotnet --list-runtimes
```
يجب أن ترى سطراً يبدأ بـ`Microsoft.AspNetCore.App 9.`

> ⚠️ **لا تستعمل `dotnet --version`** — فهو يسأل عن الـSDK وهو غير مثبَّت (ولا يلزم).

### د-3) IIS لخدمة الواجهة

```powershell
# على Windows Server:
Install-WindowsFeature -Name Web-Server -IncludeManagementTools

# على Windows 11 Pro بدلاً منه:
# Enable-WindowsOptionalFeature -Online -FeatureName IIS-WebServerRole, IIS-WebServer, IIS-StaticContent, IIS-DefaultDocument, IIS-ManagementConsole -All
```

> ⚠️ **بلا `Web-Asp-Net45`** — الواجهة **ملفات ثابتة فقط**، وتثبيت ASP.NET القديم يضيف
> سطح هجومٍ بلا فائدة. (النسخة السابقة كانت تطلبه.)

### د-4) هيكل المجلدات

```powershell
'C:\DMS\api','C:\DMS\app','C:\DMS\data\storage','C:\DMS\data\backups','C:\DMS\releases' |
    ForEach-Object { New-Item -ItemType Directory -Force -Path $_ | Out-Null }

# 🔴 محرّك SQL يكتب النسخة بحسابه هو لا بحساب التطبيق — فبلا هذا الإذن تفشل كل نسخة
#    احتياطية بـ«Operating system error 5 (Access is denied)».
icacls "C:\DMS\data\backups" /grant '"NT SERVICE\MSSQL$SQLEXPRESS":(OI)(CI)(M)'

Get-ChildItem C:\DMS
```

## 6) المرحلة هـ — بناء النظام ونقله

> **كل ما في هذه المرحلة يُنفَّذ على جهاز التطوير (`D:\DMS`) لا على السيرفر.**

### هـ-1) بناء الباك-إند

```powershell
cd D:\DMS\backend
dotnet publish Dms.Api -c Release -r win-x64 --self-contained false -o "C:\temp\dms-publish"
```

> `--self-contained false` يعني الاعتماد على .NET المثبَّت على السيرفر — حجمٌ أصغر
> وتحديثات أمنية تصل عبر Windows Update.

**تحقّق أن السكربت التشغيليّ وصل، وأن أسرار التطوير لم تصل:**
```powershell
Test-Path "C:\temp\dms-publish\ops\update-dms.ps1"          # يجب True
Test-Path "C:\temp\dms-publish\appsettings.Development.json" # يجب False
```

### هـ-2) بناء الواجهة — 🔴 **بعنوان دومينك**

```powershell
cd D:\DMS\app
flutter build web --release --dart-define=API_BASE_URL=https://dms.<دومينك>.com/api
```

> 🔴 **هذه أخطر خطوةٍ يسهل الخطأ فيها.** العنوان **يُخبَز داخل حزمة الواجهة**. لو بنيتَها
> بلا الوسم، بقي العنوان `http://localhost:5080/api` — ومعناه أن **كل متصفّح سيطلب الـAPI
> من جهاز صاحبه هو**: شاشة الدخول تظهر، وزرّ الدخول لا يعمل، بلا رسالة خطأٍ مفهومة.

**تأكّد أن العنوان دخل فعلاً في البناء:**
```powershell
Select-String -Path "D:\DMS\app\build\web\main.dart.js" -Pattern "dms\.<دومينك>\.com" -Quiet
```
يجب أن يطبع **`True`**. لو طبع `False` أعِد البناء — ولا تنشر.

### هـ-3) النقل إلى السيرفر

```powershell
$dest = "\\192.168.1.100\c$\DMS"
robocopy "C:\temp\dms-publish"      "$dest\api" /E /NFL /NDL /NJH /NJS
robocopy "D:\DMS\app\build\web"     "$dest\app" /MIR /NFL /NDL /NJH /NJS
```

> 🔴 **لاحظ الفرق:** `api` بـ**`/E`** لا `/MIR`.
> `/MIR` **يحذف كل ما في الوجهة وليس في المصدر** — أي أنه سيمحو `appsettings.Production.json`
> (**مفاتيح التوقيع**) في أول تحديثٍ لاحق. أما `app` فمرآةٌ نظيفة (ملفات ثابتة لا غير).
> **وللتحديثات المستقبلية استعمل [سكربت التحديث](#14-تحديث-النظام) لا هذه الأوامر.**

## 7) المرحلة و — الأسرار والقاعدة والخدمة

> **كل ما يلي يُنفَّذ على السيرفر** في PowerShell **كمسؤول**.

### و-1) توليد أسرار الإنتاج — **مرّة واحدة في عمر النظام**

```powershell
cd C:\DMS\api
.\Dms.Api.exe generate-secrets `
    --out      C:\DMS\api\appsettings.Production.json `
    --origins  https://dms.<دومينك>.com `
    --db-server ".\SQLEXPRESS" `
    --db-name  DmsDb `
    --storage  C:\DMS\data\storage `
    --backup   C:\DMS\data\backups
```

**ما يفعله الأمر تلقائياً:**

| المفتاح | القيمة |
|---|---|
| `Jwt:SigningKey` | مفتاح عشوائي ٦٤ بايت |
| `QrSigning:PrivateKeyBase64` / `PublicKeyBase64` | زوج ECDSA P-256 |
| `QrSigning:PublicBaseUrl` | **يُشتقّ من `--origins`** ← صفحة التحقق العامّة |
| `Urls` | `http://localhost:5080` |
| `Seed:AdminUsername` / `AdminPassword` | `admin` + **كلمة مرور عشوائية فريدة تُطبع على الشاشة** |
| `ConnectionStrings:Default` | اتصالٌ بمصادقة ويندوز |
| `AllowedOrigins` | دومينك |

> 🔴 **اكتب كلمة مرور المدير الظاهرة على الشاشة الآن** — تُطبع مرّة واحدة، وهي في الملف
> أيضاً. النظام يُجبرك على تغييرها عند أول دخول.
>
> ⚠️ **`--db-server ".\SQLEXPRESS"` بالنقطة والشرطة المائلة** — النسخة Express تُثبَّت
> **مثيلاً مُسمّى**، و`.` وحدها تعني المثيل الافتراضيّ غير الموجود.

### و-2) تأمين ملف الأسرار

```powershell
icacls "C:\DMS\api\appsettings.Production.json" /inheritance:r /grant:r "SYSTEM:(R)" /grant:r "Administrators:(F)"
```

🔴 **وانسخ الملف الآن إلى مكانٍ آمن خارج السيرفر** (فلاشة مشفّرة أو مدير كلمات مرور).
بلا هذه النسخة، عطلٌ في الجهاز يعني **أن كل كتابٍ وقّعته الشركة لم يعُد يمكن التحقق منه**.

### و-3) أول إقلاع — تطبيق قاعدة البيانات

```powershell
cd C:\DMS\api
$env:ASPNETCORE_ENVIRONMENT = "Production"
.\Dms.Api.exe
```

انتظر حتى تظهر:
```
info: Microsoft.Hosting.Lifetime[14]
      Now listening on: http://localhost:5080
```

ثم **Ctrl+C** لإيقافه. التطبيق أنشأ القاعدة، وطبّق **٢٨ مهاجرة**، وأنشأ حساب المدير.

**تحقّق في SSMS** (Server name: `.\SQLEXPRESS` · Windows Authentication):
```sql
USE DmsDb;
SELECT COUNT(*) AS Migrations FROM __EFMigrationsHistory;   -- يجب 28
SELECT Username, Role, MustChangePassword FROM Users;        -- يجب admin / SuperAdmin / 1
```

> 🔴 **لو ظهر `Username` فارغاً، توقّف** — ملف الأسرار بلا قسم `Seed`. احذف صفّ المستخدم
> وأعِد توليد الملف بـ`--force` بعد أخذ نسخةٍ منه.
>
> **لو فشل الاتصال بالقاعدة**: التطبيق يتصل بمصادقة ويندوز، وسيعمل لاحقاً بحساب
> `NT AUTHORITY\SYSTEM` (الخدمة). SQL Server يمنحه صلاحيةً كاملة افتراضياً. لو لم يفعل:
> ```sql
> IF NOT EXISTS (SELECT 1 FROM sys.server_principals WHERE name = 'NT AUTHORITY\SYSTEM')
>     CREATE LOGIN [NT AUTHORITY\SYSTEM] FROM WINDOWS;
> ALTER SERVER ROLE sysadmin ADD MEMBER [NT AUTHORITY\SYSTEM];
> ```
> ⚠️ **ولماذا `sysadmin` لا `db_owner`؟** لأن **استعادة النسخة الاحتياطية**
> (`RESTORE DATABASE`) تحتاج صلاحيةً على مستوى الخادم لا على مستوى القاعدة. وحسابٌ بـ
> `db_owner` وحده يجعل زرّ «استعادة» يفشل **يوم تحتاجه فعلاً** لا قبله.

### و-4) تسجيل الخدمة

```powershell
sc.exe create DmsApi binPath= "C:\DMS\api\Dms.Api.exe" start= auto DisplayName= "DMS API Service"
sc.exe description DmsApi "نظام إدارة الوثائق الإلكتروني"

# 🔴 لا تُقلع قبل قاعدة البيانات — وإلا تعطّلت عند كل إعادة تشغيلٍ للجهاز.
sc.exe config DmsApi depend= 'MSSQL$SQLEXPRESS'

# تعافٍ تلقائي من أي توقّف
sc.exe failure DmsApi reset= 86400 actions= restart/30000/restart/30000/restart/60000

# بيئة الإنتاج صراحةً
Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\DmsApi" `
    -Name "Environment" -Value @("ASPNETCORE_ENVIRONMENT=Production") -Type MultiString

Start-Service DmsApi
Get-Service DmsApi
```

> ⚠️ **`depend=` بعلامتَي اقتباس مفردتين** — لأن `$` في PowerShell يعني «متغيّر»، وبالمزدوجة
> يتحوّل `MSSQL$SQLEXPRESS` إلى `MSSQL` فتفشل التبعية بصمت.

**تحقّق أن الـAPI يستجيب:**
```powershell
Invoke-RestMethod -Uri "http://localhost:5080/api/system/status"
```
يجب أن يعيد: `maintenance : False`

### و-5) نشر الواجهة على IIS

```powershell

# 🔴 أوقف الموقع الافتراضي أولاً — وإلا تعارض المنفذ 80 ولم يُقلع موقعك.
Stop-Website -Name "Default Web Site" -ErrorAction SilentlyContinue

New-Website -Name "DmsApp" -Port 80 -PhysicalPath "C:\DMS\app" -Force
Start-Website -Name "DmsApp"

# قراءةٌ لحساب IIS
icacls "C:\DMS\app" /grant "IIS_IUSRS:(OI)(CI)(RX)"

Get-Website | Select-Object Name, State, PhysicalPath
```

**تحقّق على السيرفر نفسه:**
```powershell
(Invoke-WebRequest "http://localhost/" -UseBasicParsing).StatusCode        # 200
(Invoke-WebRequest "http://localhost/canvaskit/canvaskit.wasm" -UseBasicParsing).StatusCode  # 200
```

> 🔴 **الطلب الثاني هو المهمّ.** IIS لا يعرف نوع `.wasm` افتراضياً فيردّ **404**، ومحرّك

> وهو يُبنى معها تلقائياً. **لو ردّ 404 فالملف لم يصل؛ تأكّد من نسخ مجلد `build\web` كاملاً.**

## 8) المرحلة ز — نفق Cloudflare

> **ما هو؟** بدل فتح منافذ في راوترك (خطير)، برنامجٌ صغير على السيرفر يفتح **هو** اتصالاً
> صادراً آمناً إلى Cloudflare. الزوّار يصلون Cloudflare وهو يمرّر الطلبات عبر النفق.
> **صفر منافذ مفتوحة.**

### ز-1) تثبيت cloudflared

1. من `https://github.com/cloudflare/cloudflared/releases/latest` نزّل **`cloudflared-windows-amd64.msi`**
2. انقله للسيرفر وثبّته.

```powershell
cloudflared --version
```

### ز-2) تسجيل الدخول وإنشاء النفق

```powershell
cloudflared tunnel login          # سيفتح المتصفح: سجّل الدخول واختر دومينك ← Authorize
cloudflared tunnel create dms-tunnel
cloudflared tunnel list
```

📝 **دوّن الـID الظاهر** (`xxxxxxxx-xxxx-…`) — ستحتاجه في الخطوة التالية.

### ز-3) ملف الإعدادات — 🔴 **بمسارَين لا مسارٍ واحد**

أنشئ `C:\Users\Administrator\.cloudflared\config.yml` بهذا المحتوى:

```yaml
tunnel: <الـID الذي دوّنته>
credentials-file: C:\Users\Administrator\.cloudflared\<الـID>.json

ingress:
  # 1️⃣ الـAPI وصفحة التحقق العامّة ← تطبيق DMS على 5080
  #    🔴 هذه القاعدة **قبل** التالية — النفق يطابق بالترتيب وأول مطابقةٍ تفوز.
  - hostname: dms.<دومينك>.com
    path: ^/(api|v)(/|$)
    service: http://localhost:5080

  # 2️⃣ كل ما عداه ← الواجهة على IIS
  - hostname: dms.<دومينك>.com
    service: http://localhost:80

  # 3️⃣ أي مضيفٍ آخر يُردّ
  - service: http_status:404
```

> 🔴 **هذا أهمّ ملفٍّ في المرحلة كلّها.** النسخة السابقة من الدليل كانت تمرّر **كل شيء**
> إلى المنفذ 80 — أي إلى IIS الذي لا يحمل إلا ملفاتٍ ثابتة. النتيجة: **`/api` و`/v`
> يردّان 404**، فلا دخول ولا تحقّق ولا أيّ وظيفة.
>
> - **`/api/*`** → كل نداءات الواجهة
> - **`/v/*`** → صفحة التحقق التي تفتحها كاميرا الهاتف (ADR-043)

### ز-4) ربط الدومين بالنفق

```powershell
cloudflared tunnel route dns dms-tunnel dms.<دومينك>.com
```

### ز-5) الاختبار ثم التثبيت كخدمة

**اختبر يدوياً أولاً:**
```powershell
cloudflared tunnel run dms-tunnel
```

من **هاتفك على بيانات الجوال** (لا واي-فاي المكتب): افتح `https://dms.<دومينك>.com`
← يجب أن تظهر شاشة دخول DMS. ثم **Ctrl+C**.

**ثبّته خدمةً تعمل مع الإقلاع:**
```powershell
cloudflared service install

# ⚠️ الخدمة تعمل بحساب SYSTEM وتقرأ إعداداتها من مجلدٍ آخر — انسخها إليه صراحةً.
$sys = "C:\Windows\System32\config\systemprofile\.cloudflared"
New-Item -ItemType Directory -Force -Path $sys | Out-Null
Copy-Item "$env:USERPROFILE\.cloudflared\*" $sys -Force

Restart-Service Cloudflared
Get-Service Cloudflared
```
يجب أن تقرأ **`Running`**.

### ز-6) إعدادات الأمان في Cloudflare

من لوحة Cloudflare ← اختر دومينك:

| الإعداد | الموضع | القيمة |
|---|---|---|
| **Always Use HTTPS** | SSL/TLS ← Edge Certificates | ✅ مُفعّل |
| **Automatic HTTPS Rewrites** | SSL/TLS ← Edge Certificates | ✅ مُفعّل |
| **Encryption Mode** | SSL/TLS ← Overview | **Full** |
| **Bot Fight Mode** | Security ← Bots | ✅ مُفعّل |

**(اختياري) حماية إضافية:**

- **Security ← WAF ← Tools** — اسمح بالعراق ودول موظفيك فقط.
- **Cloudflare Access** (تسجيل دخولٍ ثانٍ قبل الوصول للنظام):
  > 🔴 **إن فعّلته فاستثنِ `/v/*` و`/api/verify`** — وإلا حُجبت **الجهات الخارجية كلُّها**
  > عن صفحة التحقق، وهي المقصودة بالميزة أصلاً (وزارة تمسح ختم كتابك بكاميرا هاتفها لا
  > تملك حساباً عندك ولن تُنشئ واحداً).

## 9) المرحلة ح — النسخ الاحتياطي

> **المبدأ ٣-٢-١:** ثلاث نسخ · على وسيطين مختلفين · واحدة **خارج المبنى**.
> 🔴 **والنسخة التي لا تُستعاد ليست نسخة.**

### ح-1) النسخة الأولى — تلقائية على قرص السيرفر

من داخل النظام بحساب **SuperAdmin** ← **الإعدادات ← النسخ الاحتياطي**:

1. فعّل **الجدولة التلقائية**
2. **يومي** على الساعة **٢ صباحاً**
3. احفظ

**النظام يحتفظ تلقائياً بـ**: آخر ٧ يومية · ٤ أسبوعية · ١٢ شهرية — ويحذف الأقدم.

> ⚠️ **النسخ المجدولة قاعدة البيانات فقط** (خفيفة وسريعة) — والمرفقات تُنسَخ بالمرآة اليدوية
> في ح-3. هذا قرارٌ مقصود (ADR-020) لا نقص.

### ح-2) النسخة الثانية — سحابية (OneDrive)

> ⚠️ **لماذا لا نجعل مسار النسخ داخل OneDrive مباشرةً؟** لأن أمر النسخ ينفّذه **محرّك SQL
> Server بحسابه هو**، وهو لا يملك صلاحيةً على مجلدٍ داخل ملفّ مستخدم. الصحيح: SQL يكتب
> محلياً، **ومهمّةٌ مجدولة تنسخ** — وهي تعمل بحسابك أنت.

1. ثبّت OneDrive وسجّل الدخول **بحسابٍ يخصّك وحدك** لا يعرفه أيّ موظف.
2. أنشئ مجلداً باسم `DMS-Backups` داخل OneDrive.
3. أنشئ مهمّة يومية تنسخ إليه:

```powershell
$src = "C:\DMS\data\backups"
$dst = "$env:USERPROFILE\OneDrive\DMS-Backups"
New-Item -ItemType Directory -Force -Path $dst | Out-Null

$action  = New-ScheduledTaskAction -Execute "robocopy.exe" `
           -Argument "`"$src`" `"$dst`" /MIR /R:2 /W:5 /NFL /NDL /NJH /NJS"
$trigger = New-ScheduledTaskTrigger -Daily -At 3:00AM
Register-ScheduledTask -TaskName "DMS-Backup-To-OneDrive" -Action $action -Trigger $trigger `
    -RunLevel Highest -Description "رفع النسخ الاحتياطية إلى OneDrive"

Start-ScheduledTask -TaskName "DMS-Backup-To-OneDrive"   # جرّبها الآن
```

> 🔴 **OneDrive لا يزامن والجهاز مسجَّلٌ خروجه.** أبقِ حساب Administrator **مسجَّلاً دخوله
> والشاشة مقفلة** (`Win+L`) — لا «Sign out». وتحقّق شهرياً أن الملفات تصل فعلاً.

### ح-3) النسخة الثالثة — مرآة كاملة على قرصٍ خارجي (شهرياً)

1. وصّل القرص الخارجي بالسيرفر (لنقل أنه `E:`).
2. من النظام: **النسخ الاحتياطي ← مرآة كاملة إلى مسار خارجي** ← اكتب `E:\DMS-Mirror`.
3. انتظر انتهاءها (تشمل **القاعدة + كل المرفقات**).
4. 🔴 **افصل القرص واحمله خارج المبنى** — حريقٌ أو سرقةٌ تأخذ الجهاز والقرص معاً إن بقيا معاً.

## 10) المرحلة ط — الاختبار النهائي

> **لا تُعلن النظام جاهزاً قبل أن تضع علامةً على كل سطر.**

### أ) الوصول

- [ ] `https://dms.<دومينك>.com` يفتح من **كمبيوتر داخل المكتب**
- [ ] يفتح من **هاتف على بيانات الجوال** (لا واي-فاي المكتب)
- [ ] **القفل الأخضر** (شهادة HTTPS) ظاهر في المتصفح
- [ ] الدخول بـ`admin` وكلمة المرور المولَّدة يعمل، **ويطلب تغييرها**
- [ ] بعد التغيير، الخروج والدخول بالكلمة الجديدة يعمل

### ب) الوظائف الأساسية

- [ ] إنشاء شركة (سوبر أدمن) ← ثم جهة ← ثم قالب
- [ ] إنشاء مستخدمٍ جديد ومنحه صلاحيات، والدخول به
- [ ] إنشاء **كتاب صادر** واعتماده ← يحصل على **رقمٍ رسميّ**
- [ ] توليد **PDF** يعمل، وفيه الترويسة **وختم QR**
- [ ] رفع **مرفق** يعمل، وفتحه يعمل
- [ ] إنشاء **كتاب وارد** وإحالته لقسم
- [ ] **تقرير** واحد على الأقل يُصدَّر PDF وExcel

### ج) 🔴 التحقق بكاميرا الهاتف (الميزة الجديدة)

- [ ] افتح كاميرا هاتفك **العادية** ووجّهها لختم QR في الـPDF المطبوع أو على الشاشة
- [ ] يظهر إشعارٌ برابط `https://dms.<دومينك>.com/v/…` ← اضغطه
- [ ] تفتح صفحةٌ عربية: **«تم إصدار هذا الكتاب فعلاً من الشركة»** مع الرقم والتاريخ والجهة
- [ ] **لا يظهر المبلغ** في الصفحة
- [ ] زرّ **«تنزيل الكتاب PDF»** يعمل
- [ ] جرّب رابطاً مُبدَّل الحروف ← **«تم التلاعب بالكتاب»** بلا أي بيانات

> ⚠️ **لو ظهر نصٌّ خامّ بدل رابط**، فـ`PublicBaseUrl` لم يُضبط قبل اعتماد الكتاب.
> راجع [§11](#11-أول-كتاب-رسمي--نقطة-اللاعودة) **قبل** إصدار أي كتابٍ رسميّ.

### د) استمرارية الخدمة

- [ ] **أعِد تشغيل الـMini PC** ← يعود النظام تلقائياً خلال دقيقتين بلا تدخّل
- [ ] `Get-Service DmsApi, Cloudflared, 'MSSQL$SQLEXPRESS'` ← ثلاثتها `Running`
- [ ] **افصل كيبل الكهرباء عن UPS** ← الجهاز يبقى يعمل، والبرنامج ينبّه ← أعِد التوصيل
- [ ] شاشة **سجلّ التدقيق** تعرض ما فعلتَه أعلاه

### هـ) 🔴 اختبار الاستعادة — **غير قابل للتفاوض**

1. خذ نسخةً يدوية: **النسخ الاحتياطي ← نسخة الآن**
2. أنشئ كتاباً صادراً بعنوان **«اختبار الاستعادة»** واعتمده
3. **استعِد النسخة التي أخذتَها في الخطوة 1** من شاشة الاستعادة
4. ✅ **الكتاب اختفى** ← الاستعادة تعمل فعلاً

> **لماذا هذا إلزاميّ؟** نسخةٌ لم تُختبر استعادتها **ليست نسخة — هي أمنيةٌ وهمية**.
> اليوم الذي تحتاجها فيه ليس اليوم المناسب لاكتشاف أنها لا تعمل.

## 11) أول كتاب رسمي — نقطة اللاعودة

> **اقرأ هذا القسم قبل أن يُصدر أحدٌ في شركتك كتاباً رسمياً واحداً.**

### 🔴 ثلاثة أشياء تُخبَز في الـPDF لحظة الاعتماد

عند اعتماد أيّ كتاب، يُولَّد ختم QR **ويُدفن في ملف الـPDF نهائياً**. وهو يحمل:

1. **توقيعاً بمفتاح `QrSigning:PrivateKeyBase64`** — تغيير المفتاح يُبطل التحقق من كل
   كتابٍ سابق.
2. **رابطاً مبنياً على `QrSigning:PublicBaseUrl`** — تغيير الدومين يجعل كل رابطٍ سابق ميتاً.
3. **رقم الكتاب** — من تسلسل الشركة.

**فتصحيح أيٍّ من هذين لاحقاً لا يمسّ ورقةً طُبعت.** الكتب القديمة تبقى بالقيم القديمة **إلى
الأبد**.

### ✅ قائمة ما قبل أول كتاب

```powershell
# اقرأ ملف الإنتاج وتأكّد أن الثلاثة مضبوطة
$cfg = Get-Content C:\DMS\api\appsettings.Production.json -Raw | ConvertFrom-Json
$cfg.QrSigning.PublicBaseUrl      # يجب: https://dms.<دومينك>.com  (لا فارغاً)
$cfg.QrSigning.PrivateKeyBase64.Length -gt 100   # يجب True
$cfg.AllowedOrigins               # يجب: https://dms.<دومينك>.com
```

- [ ] `PublicBaseUrl` = دومينك النهائيّ **بلا `/` في آخره**
- [ ] نسخةٌ من `appsettings.Production.json` محفوظة **خارج السيرفر** في مكانٍ مشفّر
- [ ] اجتزتَ اختبار كاميرا الهاتف في [§10-ج](#ج--التحقق-بكاميرا-الهاتف-الميزة-الجديدة)
- [ ] اجتزتَ اختبار الاستعادة في [§10-هـ](#هـ-اختبار-الاستعادة--غير-قابل-للتفاوض)
- [ ] الدومين عليه **تجديدٌ تلقائي** وبطاقتك سارية

## 14) تحديث النظام

**على جهاز التطوير:**
```powershell
cd D:\DMS\backend
dotnet publish Dms.Api -c Release -r win-x64 --self-contained false -o "C:\temp\dms-new"

cd D:\DMS\app
flutter build web --release --dart-define=API_BASE_URL=https://dms.<دومينك>.com/api
```

> ⚠️ **الوسم مطلوبٌ في كل بناء** — نسيانُه يُنتج واجهةً تشير إلى `localhost` وتتعطّل عند
> كل مستخدم.

**النقل:**
```powershell
robocopy "C:\temp\dms-new"          "\\192.168.1.100\c$\temp\dms-new" /MIR /NFL /NDL /NJH /NJS
robocopy "D:\DMS\app\build\web"     "\\192.168.1.100\c$\DMS\app"      /MIR /NFL /NDL /NJH /NJS
```

**على السيرفر — سكربتٌ واحد يفعل كل شيء بأمان:**
```powershell
powershell -File "C:\DMS\api\ops\update-dms.ps1" -SourceDir "C:\temp\dms-new"
```

يفعل بالترتيب: تحقّق من المتطلبات → **يطلب نسخةً احتياطية** → يوقف الخدمة → **يؤرشف
الإصدار الحالي** في `C:\DMS\releases\` → ينسخ الجديد **مع استثناء ملف الأسرار وبيانات
التشغيل** → يشغّل الخدمة → يفحص الصحّة. وإن فشل الفحص **طبع لك أمر الرجوع**.

## 15) استكشاف الأخطاء

### لا يفتح الموقع إطلاقاً

```powershell
# 1) الخدمات الثلاث
Get-Service DmsApi, Cloudflared, 'MSSQL$SQLEXPRESS'

# 2) الـAPI محلياً
Invoke-RestMethod "http://localhost:5080/api/system/status"

# 3) الواجهة محلياً
(Invoke-WebRequest "http://localhost/" -UseBasicParsing).StatusCode

# 4) سجلّ التطبيق (لاحظ: المصدر Dms.Api لا DmsApi)
Get-EventLog -LogName Application -Source "Dms.Api" -Newest 20 | Format-List TimeGenerated, Message
```

| النتيجة | السبب والعلاج |
|---|---|
| خدمةٌ متوقّفة | `Start-Service <الاسم>` — ثم افحص السجلّ لمعرفة سبب التوقّف |
| 1 و2 و3 تعمل والموقع لا يفتح | **النفق** — `Restart-Service Cloudflared`، وراجع `config.yml` |
| DmsApi تتوقّف فور تشغيلها | أسرارٌ ناقصة أو قاعدةٌ غير متاحة — السجلّ يقول أيّهما |

### الصفحة تفتح بيضاء

```powershell
(Invoke-WebRequest "http://localhost/canvaskit/canvaskit.wasm" -UseBasicParsing).StatusCode
```
**404** ⇒ ملف `web.config` غير موجود في `C:\DMS\app` — أعِد نسخ `build\web` كاملاً.

### شاشة الدخول تظهر وزرّ الدخول لا يفعل شيئاً

🔴 **الواجهة بُنيت بلا `--dart-define`.** افتح أدوات المطوّر (F12) ← **Network** ← ستجد
طلباتٍ إلى `localhost:5080` فاشلة. **العلاج: أعِد البناء بالوسم وانشر** ([§14](#14-تحديث-النظام)).

### `/api` أو `/v` يردّان 404 من الإنترنت وهما يعملان محلياً

قاعدة المسار في `config.yml` ناقصةٌ أو ترتيبها خاطئ ([§8-ز-3](#ز-3-ملف-الإعدادات--بمسارَين-لا-مسارٍ-واحد)).
قاعدة `path:` **يجب أن تسبق** قاعدة المنفذ 80.

### كل النسخ الاحتياطية تفشل

رسالة `Operating system error 5` ⇒ محرّك SQL لا يملك صلاحية الكتابة:
```powershell
icacls "C:\DMS\data\backups" /grant '"NT SERVICE\MSSQL$SQLEXPRESS":(OI)(CI)(M)'
Restart-Service 'MSSQL$SQLEXPRESS'
```

### امتلأ القرص

```powershell
Get-PSDrive C | Select-Object Used, Free
Get-ChildItem "C:\DMS\data\backups" | Sort-Object LastWriteTime | Select-Object -First 5
Get-ChildItem "C:\DMS\releases"     | Sort-Object LastWriteTime   # نقاط رجوع قديمة — احذف الأقدم
```
النظام يحذف النسخ المتقادمة تلقائياً؛ نقاط الرجوع في `releases\` **لا** تُحذف تلقائياً.

### نسيت كلمة مرور المدير

- **الحلّ الأول:** ادخل بحساب سوبر أدمن ثانٍ وأعِد تعيينها من شاشة المستخدمين.
  🔑 **ولهذا أنشئ حساب سوبر أدمن احتياطياً من اليوم الأول.**
- **إن لم يوجد:** تواصل مع المطوّر — تُعاد التهيئة من قاعدة البيانات.

### انتهت شهادة HTTPS

لا يحدث — **Cloudflare يجدّدها تلقائياً** بلا تدخّل.

## 16) المرجع السريع

### عناوين ومسارات

| ما هو | القيمة |
|---|---|
| عنوان النظام للجميع | `https://dms.<دومينك>.com` |
| صفحة التحقق العامّة | `https://dms.<دومينك>.com/v/<token>` |
| IP السيرفر داخل المكتب | `192.168.1.100` |
| الـAPI (على السيرفر) | `http://localhost:5080` |
| الواجهة (على السيرفر) | `http://localhost:80` |
| مجلد التطبيق | `C:\DMS\api\` |
| مجلد الواجهة | `C:\DMS\app\` |
| المرفقات | `C:\DMS\data\storage\` |
| النسخ الاحتياطية | `C:\DMS\data\backups\` |
| نقاط الرجوع | `C:\DMS\releases\` |
| **ملف الأسرار** 🔑 | `C:\DMS\api\appsettings.Production.json` |
| إعداد النفق | `C:\Users\Administrator\.cloudflared\config.yml` |

### أوامر الطوارئ

```powershell
# إعادة تشغيل النظام كاملاً
Restart-Service 'MSSQL$SQLEXPRESS'; Start-Sleep 10; Restart-Service DmsApi; Restart-Service Cloudflared

# حالة كل شيء
Get-Service DmsApi, Cloudflared, 'MSSQL$SQLEXPRESS' | Format-Table Name, Status, StartType

# فحص صحّة
Invoke-RestMethod "http://localhost:5080/api/system/status"

# آخر الأخطاء
Get-EventLog -LogName Application -EntryType Error -Newest 10 | Format-List TimeGenerated, Source, Message

# نسخة احتياطية فورية: من داخل النظام ← الإعدادات ← النسخ الاحتياطي ← «نسخة الآن»
```

### مفاتيح يجب حفظها

| المفتاح | أين | ماذا يحدث لو ضاع |
|---|---|---|
| كلمة مرور Administrator (ويندوز) | مدير كلمات مرور | **لا دخول للسيرفر إطلاقاً** |
| **مفتاح استرداد BitLocker** | فلاشة خارج الجهاز | **لا يُفتح القرص** لو تعطّل اللوح الأمّ |
| 🔴 **`appsettings.Production.json`** | نسخة مشفّرة خارج السيرفر | **كل كتابٍ وقّعته الشركة لا يُتحقّق منه بعد اليوم** |
| كلمة مرور Cloudflare + رموز الاسترداد | مدير كلمات مرور | **فقدان السيطرة على الدومين** |
| كلمة مرور مدير DMS | + حساب سوبر أدمن ثانٍ للطوارئ | قابل للحل بالحساب الثاني |

> ⚠️ **الأخطر بلا منازع:** `QrSigning:PrivateKeyBase64` داخل ملف الأسرار. احتفظ بنسخةٍ
> مشفّرة منه **خارج السيرفر**، وجدّد هذه النسخة إن أعدتَ توليد الملف يوماً.

## ملحق: ما صُحِّح ولماذا

> راجعتُ نسخة **2026-08-18** سطراً بسطر مقابل الكود قبل كتابة هذه. الأخطاء التالية كانت
> فيها، وكلُّها **مقيسة على الكود لا مُستنتَجة**.

### خمسةٌ كانت ستمنع النظام من العمل

| # | العطل في النسخة السابقة | الأثر | العلاج هنا |
|---|---|---|---|
| ١ | لا ذكر لعنوان الـAPI في الواجهة (كان مثبّتاً على `localhost:5080`) | كل متصفّح يطلب الـAPI **من جهاز صاحبه** — لا دخول إطلاقاً | `--dart-define=API_BASE_URL` + تحقّقٌ بعد البناء ([هـ-2](#هـ-2-بناء-الواجهة--بعنوان-دومينك)) |
| ٢ | النفق يمرّر **كل شيء** إلى المنفذ 80 | `/api` و`/v` يردّان 404 | قاعدة `path:` قبل قاعدة المنفذ 80 ([ز-3](#ز-3-ملف-الإعدادات--بمسارَين-لا-مسارٍ-واحد)) |
| ٣ | افتراض المنفذ 5080 بلا مصدرٍ في الإنتاج | الخادم يستمع على **5000** فلا يجده النفق | `Urls` يُكتب في ملف الأسرار تلقائياً |
| ٤ | لا تنبيه لفخّ حساب المدير الأول | سوبر أدمن **باسمٍ وكلمة مرورٍ فارغين** — قفلٌ تامّ | كلمةٌ عشوائية تُولَّد وتُطبع + معالجةٌ في الكود |
| ٥ | لا ذكر لـ`PublicBaseUrl` (الدليل أسبق من الميزة) | كاميرا الهاتف لا تفتح شيئاً — **ولا يُصلَح بأثرٍ رجعيّ** | يُشتقّ من `--origins` تلقائياً + [§11](#11-أول-كتاب-رسمي--نقطة-اللاعودة) |

### سبعةٌ كانت ستُعطّل جزءاً

| العطل | العلاج |
|---|---|
| IIS بلا نوع `.wasm` ⇒ صفحةٌ بيضاء | `web.config` يُبنى مع الواجهة تلقائياً |
| `robocopy /MIR` على مجلد التطبيق ⇒ **يمحو ملف الأسرار** | `/E` للنشر الأول، وسكربت التحديث بعده |
| مسار النسخ داخل OneDrive ⇒ محرّك SQL لا يملك صلاحيته | نسخٌ محليّ + **مهمّة مجدولة** ترفع ([ح-2](#ح-2-النسخة-الثانية--سحابية-onedrive)) |
| «غيّر مسار النسخ من شاشة النظام» — **شاشةٌ لا وجود لها** | المسار من ملف الإعدادات، والمرآة اليدوية لها شاشتها |
| OneDrive لا يزامن والجهاز مسجَّلٌ خروجه | تنبيهٌ صريح: أقفل الشاشة ولا تسجّل الخروج |
| مسار `ops\update-dms.ps1` خاطئ ولا يصل السيرفر | صار يُنشَر مع التطبيق تلقائياً |
| BitLocker غير مثبّت على Windows Server | `Install-WindowsFeature BitLocker` أولاً |

### وستُّ نقاط دقّة

- **الترخيص**: التقييمية تعمل ١٨٠ يوماً ثم يُطفأ الجهاز كل ساعة — صار تحذيراً صريحاً.
- **`dotnet --version`** يسأل عن SDK غير المثبَّت ⇒ `dotnet --list-runtimes`.
- **عدد المهاجرات 28** لا «23 أو أكثر».
- **مصدر سجلّ الأحداث `Dms.Api`** لا `DmsApi`.
- **TCP/IP والمنفذ 1433 لا يلزمان** — التطبيق على الجهاز نفسه.
- **`sysadmin` لا `db_owner`** — لأن **الاستعادة** تحتاج صلاحيةً على مستوى الخادم، وحسابٌ
  بـ`db_owner` يجعل زرّ الاستعادة يفشل **يوم تحتاجه**.

### وثلاثة إصلاحاتٍ في الكود رافقت هذه المراجعة

| الإصلاح | لماذا |
|---|---|
| `UseForwardedHeaders` | خلف النفق كان كلُّ زوّار العالم يظهرون بعنوان `127.0.0.1`: **حدُّ الطلبات «لكل IP» يصير حدّاً عاماً واحداً** (متحقّقٌ مُسيءٌ واحد يحجب الجميع)، وسجلّ التدقيق يدوّن عنواناً بلا معنى |
| `appsettings.Development.json` **لا يُنشَر** | كان يصل السيرفر ومعه **مفتاح توقيع QR للتطوير**، ولو غاب متغيّر البيئة أقلع النظام بيئةَ تطوير: `AllowAnyOrigin` وSwagger و**نقطة تصفير القاعدة** مفتوحة |
| `SeedCredentials` | معالجة فخّ «السلسلة الفارغة ليست `null`» في جذره |
