00 0) الحصيلة أولاً #

⟵ اسحب لرؤية بقية الجدول ⟶
الحالة ✅ النظام يعمل من الإنترنت على https://dms.nociraq.com
الدليل القاطع أُعيد تشغيل الجهاز، ولم تُلمس الحاسبة بعده، ثم فُتح النظام من حاسبةٍ ثانية ومن هاتفٍ على بيانات الجوال
ما تحقّق الدخول · تغيير كلمة المرور الأولى · الواجهة كاملةً
الخدمات الثلاث Cloudflared · DmsApi · W3SVC — كلُّها Running + Automatic
الأعطال تسعة — ظهرت كلُّها وعولجت كلُّها، وصار كلٌّ منها بنداً في الدليل الشامل
🔑

🔑 ولماذا «إعادة التشغيل» هي الحصيلة لا «فتح الموقع»؟ لأن ثلاثة من الأعطال التسعة كانت تعمل تماماً في الجلسة الجارية وتسقط عند الإقلاع. فـ«النظام يعمل» لا تعني «النظام يبقى يعمل»، والحكمُ الوحيد إقلاعةٌ نظيفة.

ما هي بيئة التجربة فعلاً #

⟵ اسحب لرؤية بقية الجدول ⟶
جهاز التطوير فيه المستودع D:\DMS + .NET SDK + Flutter
حاسبة التجربة ويندوز · SQL Server بمثيلٍ افتراضيّ (MSSQLSERVER) · IIS · بلا SDK ولا كود مصدر

01 1) قسمة العمل بين الجهازين #

🔴 أكثرُ ما أضاع وقتاً في هذه الجلسة لم يكن عطلاً تقنياً، بل تشغيلَ أمرٍ على الجهاز الخطأ. وقع مرّتين: Compress-Archive على حاسبة التجربة (والمجلّدان غير موجودين فيها)، وأوامرُ IIS على جهازٍ لا IIS فيه.

⟵ اسحب لرؤية بقية الجدول ⟶
💻 جهاز التطوير 🧪 حاسبة التجربة
dotnet publish · flutter build ✅ ❌
Compress-Archive ✅ ❌
Expand-Archive ❌ ✅
generate-secrets · sqlcmd ❌ ✅
sc.exe · Start-Service ❌ ✅
Import-Module WebAdministration · Get-Website ❌ ✅
cloudflared ❌ ✅
فتحُ المتصفّح على الدومين ✅ (وأيّ جهاز) ✅

🔑 القاعدة الحاسمة:

📌

كلُّ أمرٍ فيه build أو publish أو Compress ⟵ جهاز التطوير. وكلُّ أمرٍ فيه Expand أو Service أو IIS أو sqlcmd أو cloudflared ⟵ حاسبة التجربة. وما عدا ذلك — فتحُ المتصفّح — من أيّ جهاز.

واعرف أين أنت بسطرٍ واحد عند أيّ شكّ:

PowerShell 
if (Test-Path "C:\temp\dms-publish") { "💻 جهاز التطوير — هنا تبني وتضغط" }
elseif (Test-Path "C:\DMS\api")      { "🧪 حاسبة التجربة — هنا تفكّ وتثبّت" }
else                                  { "🧪 حاسبة التجربة (قبل فكّ الحزم)" }

02 2) المرحلة ١ — جهاز التطوير: البناء #

١-أ) بناء الباك-إند #

PowerShell 
cd D:\DMS\backend
dotnet publish Dms.Api -c Release -r win-x64 --self-contained false -o "C:\temp\dms-publish"

ما ظهر فعلاً: Build succeeded in 12.9s.

١-ب) بناء الواجهة — 🔴 بعنوان دومينك #

PowerShell 
cd D:\DMS\app
flutter build web --release --dart-define=API_BASE_URL=https://dms.nociraq.com/api
⚠️

⚠️ تحذيرات Wasm dry run findings تُتجاهَل. ظهرت في تنفيذنا، وهي استطلاعٌ استباقيّ يقول: «لو أردتَ يوماً بناءً بـWebAssembly، هذه الحزمة تمنعك». والبناء الفعليّ JavaScript، ودليلُه السطران: Compiling lib\main.dart for the Web... 88.1s ثم √ Built build\web. وtree-shaken مكسبٌ لا عطل (قلّص الخطوط 99٪).

🔴 والحارس الذي لا يُتخطّى:

PowerShell 
Select-String -Path "D:\DMS\app\build\web\main.dart.js" -Pattern "dms\.nociraq\.com" -Quiet

يجب True. ولو False أعِد البناء ولا تنشر: العنوان مخبوزٌ داخل main.dart.js، وتصحيحُه في ملفٍّ على السيرفر لا يُصلح شيئاً.

١-ج) حارسا الحزمة #

PowerShell 
Test-Path "C:\temp\dms-publish\ops\update-dms.ps1"           # يجب True
Test-Path "C:\temp\dms-publish\appsettings.Development.json" # يجب False

🔴 والثاني أهمّ من الأول. لو كان True فقد تسرّب مفتاح توقيع QR ومفتاح JWT للتطوير، وإقلاعٌ ببيئة تطويرٍ خطأً يفتح AllowAnyOrigin وSwagger ونقطةَ تصفير القاعدة. (كلاهما جاء صحيحاً في تنفيذنا — Dms.Api.csproj يضمنهما.)

١-د) الحزم #

PowerShell 
New-Item -ItemType Directory -Force -Path "D:\DMS-نشر" | Out-Null

Compress-Archive -Path "C:\temp\dms-publish\*"  -DestinationPath "D:\DMS-نشر\dms-api.zip" -Force
Compress-Archive -Path "D:\DMS\app\build\web\*" -DestinationPath "D:\DMS-نشر\dms-app.zip" -Force

Get-ChildItem "D:\DMS-نشر" | Select-Object Name, @{n='ميغابايت';e={[math]::Round($_.Length/1MB,1)}}

الأحجام الفعلية في تنفيذنا: dms-api.zip = 47.7 م.ب · dms-app.zip = 14.9 م.ب. 🔴 ولو ظهر أحدهما أقلّ من ٥ م.ب فالمجلّد المصدر فارغ أو المسار خطأ — قِف.

💡

💡 ولماذا الضغط على D: ثم النسخ للفلاشة؟ الضغطُ مباشرةً على فلاشة بطيءٌ وقد ينقطع.

03 3) المرحلة ٢ — النقل #

الأصل في دليل النشر robocopy عبر الشبكة، لكنّ مشاركة المسؤول (\\IP\c$) مُعطَّلة افتراضياً على ويندوز المنزليّ. فالمسلك المضمون:

ثلاثة ملفات على الفلاشة:

⟵ اسحب لرؤية بقية الجدول ⟶
الملف المصدر
dms-api.zip ناتج dotnet publish
dms-app.zip ناتج flutter build web
dms-trial-preflight.ps1 _scripts/dms-trial-preflight.ps1

على حاسبة التجربة:

PowerShell 
New-Item -ItemType Directory -Force -Path C:\DMS\api, C:\DMS\app | Out-Null
Expand-Archive -Path "E:\dms-api.zip" -DestinationPath "C:\DMS\api" -Force
Expand-Archive -Path "E:\dms-app.zip" -DestinationPath "C:\DMS\app" -Force
🔴

⚠️ وExpand-Archive لا يحذف القديم — فعند تحديثٍ لاحقٍ للواجهة أفرغ C:\DMS\app أولاً. 🔴 ولا تُفرغ C:\DMS\api بعد توليد الأسرار — فيه appsettings.Production.json.

⚠️ ولا تنقل مجلّد D:\DMS نفسه — حاسبة التجربة لا تحتاج كوداً مصدرياً ولا SDK.

04 4) المرحلة ٣ — الفحص المسبق #

السكربت قراءةٌ خالصة، ويفحص ستّة، ثم يطبع الأوامر التالية وقد كُتب فيها اسمُ مثيل SQL عندك ودومينك — فلا تخمّن قيمةً ولا تبدّلها بيدك.

ما أمسكه في تنفيذنا فعلاً:

05 5) المرحلة ٤ — الأسرار والقاعدة #

٤-أ) المجلدات وإذن محرّك SQL #

PowerShell 
'C:\DMS\api','C:\DMS\app','C:\DMS\data\storage','C:\DMS\data\backups' |
    ForEach-Object { New-Item -ItemType Directory -Force -Path $_ | Out-Null }

# 🔴 محرّك SQL يكتب النسخة بحسابه هو — وبلا هذا تفشل كل نسخة احتياطية بـ«Access is denied»
icacls "C:\DMS\data\backups" /grant '"NT SERVICE\MSSQLSERVER":(OI)(CI)(M)'
⚠️

⚠️ بدّل MSSQLSERVER باسم مثيلك — لو كان SQLEXPRESS فهو MSSQL$SQLEXPRESS، وحينها استعمل علامتَي اقتباسٍ مفردتين لأن $ في PowerShell يعني «متغيّر».

٤-ب) توليد الأسرار #

PowerShell 
cd C:\DMS\api
.\Dms.Api.exe generate-secrets `
    --out       C:\DMS\api\appsettings.Production.json `
    --origins   https://dms.nociraq.com `
    --db-server "." `
    --db-name   DmsTrial `
    --storage   C:\DMS\data\storage `
    --backup    C:\DMS\data\backups

🔴 يطبع كلمة مرور المدير الأول في صندوقٍ بعد سطر «كُتب الملف» — اسحب النافذة للأعلى واقرأه.

⚠️

⚠️ وعلامات ? في المخرَج هي ✔ لم يرسمها الطرفيّ — تجميليٌّ بحت، والدليل أن العربية ظهرت صحيحة.

وإن فاتتك، اقرأها من الملف — ولا تكتبها بيدك أبداً:

PowerShell 
(Get-Content C:\DMS\api\appsettings.Production.json -Raw | ConvertFrom-Json).Seed
🔴

🔴 لماذا «لا تكتبها بيدك»؟ لأننا فعلناها وفشلت. الكلمة ٢٠ حرفاً والمُدخَل كان ١٩. والمولّد يستبعد المتشابهات (l·I·O·0) لكنه يُبقي @ # % + = ? — والطرفيّةُ التي ترسم الرموز كـ? تجعل ? الحقيقيّة لا تُميَّز عن رمزٍ مشوَّه. ⚠️ وكلُّ محاولةٍ فاشلة تزيد العدّاد، وعند الخامسة يُقفل الحساب ١٥ دقيقة.

٤-ج) التحقّق من الملفّ (بلا كشف أسرار) #

PowerShell 
$c = Get-Content C:\DMS\api\appsettings.Production.json -Raw | ConvertFrom-Json
[PSCustomObject]@{
  Urls       = $c.Urls
  Connection = $c.ConnectionStrings.Default
  PublicBase = $c.QrSigning.PublicBaseUrl
  Origins    = $c.AllowedOrigins
  AdminUser  = $c.Seed.AdminUsername
  JwtLen     = $c.Jwt.SigningKey.Length
  QrPubLen   = $c.QrSigning.PublicKeyBase64.Length
} | Format-List

٤-د) تأمين الملف #

PowerShell 
icacls "C:\DMS\api\appsettings.Production.json" /inheritance:r /grant:r "SYSTEM:(R)" /grant:r "Administrators:(F)"

٤-هـ) 🔴 صلاحية حساب الخدمة — قبل الخدمة لا بعدها #

PowerShell 
sqlcmd -S . -Q "IF NOT EXISTS (SELECT 1 FROM sys.server_principals WHERE name = 'NT AUTHORITY\SYSTEM') CREATE LOGIN [NT AUTHORITY\SYSTEM] FROM WINDOWS; ALTER SERVER ROLE sysadmin ADD MEMBER [NT AUTHORITY\SYSTEM];"
sqlcmd -S . -Q "SELECT IS_SRVROLEMEMBER('sysadmin', 'NT AUTHORITY\SYSTEM') AS IsSysadmin;"   -- يجب 1

هذه الخطوة هي العطل ٤ — اقرأه، فهو أكثرُ ما أضاع وقتاً.

٤-و) أول إقلاع — إنشاء القاعدة #

PowerShell 
cd C:\DMS\api
$env:ASPNETCORE_ENVIRONMENT = "Production"
.\Dms.Api.exe

انتظر Now listening on: http://localhost:5080 ثم Ctrl+C.

PowerShell 
sqlcmd -S . -d DmsTrial -Q "SELECT COUNT(*) AS Migrations FROM __EFMigrationsHistory; SELECT Username, Role, MustChangePassword FROM Users;"

الناتج الفعليّ: Migrations = 30 · admin / 1 / 1.

🔴

🔑 وRole = 1 هو SuperAdmin (Enums.cs يبدأ التعداد من ١) — sqlcmd يقرأ العمود خاماً. 🔴 وعدد المهاجرات يُقابَل بعدد الملفات لا يُحفَظ رقماً — كان الدليل يقول ٢٨ وهو رقمُ 2026-09-10، فكان سيُسقطك في «توقّف» كاذبة. (العطل ١)

٤-ز) فحصُ الدخول محلياً — يعزل المتغيّرات قبل النفق #

PowerShell 
$cfg = Get-Content C:\DMS\api\appsettings.Production.json -Raw | ConvertFrom-Json
$r = Invoke-RestMethod -Uri "http://localhost:5080/api/auth/login" -Method Post `
     -ContentType "application/json" `
     -Body (@{ Username = $cfg.Seed.AdminUsername; Password = $cfg.Seed.AdminPassword } | ConvertTo-Json)
"طول الرمز: $($r.accessToken.Length)"

الناتج الفعليّ: 507.

🔑 وقيمةُ هذا الفحص أنه يعزل: إن نجح، فكلُّ ما بين المتصفّح والقاعدة مُثبَتٌ سليم، فأيُّ عطلٍ بعده يخصّ النفق وحده — فلا تبحث في القاعدة ولا في الخدمة.

06 6) المرحلة ٥ — الخدمة #

PowerShell 
sc.exe create DmsApi binPath= "C:\DMS\api\Dms.Api.exe" start= auto DisplayName= "DMS API Service"
sc.exe config DmsApi depend= 'MSSQLSERVER'
sc.exe failure DmsApi reset= 86400 actions= restart/30000/restart/30000/restart/60000
Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\DmsApi" `
    -Name "Environment" -Value @("ASPNETCORE_ENVIRONMENT=Production") -Type MultiString

Start-Service DmsApi
Invoke-RestMethod -Uri "http://localhost:5080/api/system/status"   # maintenance : False
🔴

⚠️ depend= بعلامتَي اقتباسٍ مفردتين — بدّل MSSQLSERVER باسم مثيلك.

🔴 ولو ردّ Start-Service بـ«Cannot start service» بلا سبب، فالرسالة لا تقول شيئاً — اقرأ سجلّ الأحداث:

PowerShell 
Get-EventLog -LogName Application -Newest 30 |
    Where-Object { $_.Source -match 'Dms|\.NET Runtime|Application Error' } |
    Select-Object TimeGenerated, Source, EntryType, Message | Format-List

07 7) المرحلة ٦ — IIS #

PowerShell 
Import-Module WebAdministration

# 🔴 يُعطَّل عن الإقلاع لا يُوقَف فحسب
Stop-Website -Name "Default Web Site" -ErrorAction SilentlyContinue
Set-ItemProperty "IIS:\Sites\Default Web Site" -Name serverAutoStart -Value $false

New-Website -Name "DmsApp" -Port 80 -PhysicalPath "C:\DMS\app" -Force
Set-ItemProperty "IIS:\Sites\DmsApp" -Name serverAutoStart -Value $true
Start-Website -Name "DmsApp"

icacls "C:\DMS\app" /grant "IIS_IUSRS:(OI)(CI)(RX)"

Get-Website | Select-Object Name, State, @{n='AutoStart';e={$_.serverAutoStart}}

🎯 المطلوب: DmsApp = Started/True · Default Web Site = Stopped/False.

$h = (Invoke-WebRequest "http://localhost/" -UseBasicParsing).Content
if ($h -match 'flutter|main\.dart\.js') { "✔ الرادّ هو DMS" } else { "✖ ما زال IIS الافتراضيّ" }

🔴 والطلب الثاني هو الحاسم. IIS لا يعرف .wasm افتراضياً فيردّ 404، ومحرّكُ الرسم لا يُقلع، فتظهر صفحةٌ بيضاء بلا رسالة خطأ — وهي أصعب أعطال النشر تشخيصاً. يعالجها web.config المرافق (يُبنى مع الواجهة تلقائياً من app/web/).

⚠️ ولا تحكم على النظام من المتصفّح هنا — ستفتح الصفحة ولن يعمل الدخول، لأن الواجهة مخبوزٌ فيها https://dms.nociraq.com/api لا localhost. وهذا سليم — ينتظر النفق.

08 8) المرحلة ٧ — النفق #

٧-أ) تحقّق أن الدومين على Cloudflare #

PowerShell 
Resolve-DnsName nociraq.com -Type NS | Select-Object NameHost

الناتج الفعليّ: pam.ns.cloudflare.com · will.ns.cloudflare.com ⇒ ✅ جاهز.

🔴 ودومينٌ خارج Cloudflare يجعل tunnel route dns يفشل بـzone not found — وهي الرسالة نفسها التي تظهر لو اخترتَ دوميناً خاطئاً عند login، فتُضلّلك عن السبب. والعلاج: لوحة Cloudflare ← Add a site ← خطة Free ← بدّل الـnameservers عند مسجّلك ← انتظر حتى Active (حتى ٢٤ ساعة — فابدأ بها وأنت تبني وتنقل).

٧-ب) التثبيت #

PowerShell

٧-ج) الدخول وإنشاء النفق #

PowerShell

🔴 يطبع رابطاً في PowerShell — وهو وحده ما يفتح صفحة التفويض. والتنقّل اليدويّ في لوحة Cloudflare لا يصل إليها أبداً (لأن الرابط يحمل callback يعيد الشهادة إلى cloudflared المنتظِر). انسخه كاملاً ← الصقه ← اختر nociraq.com ← Authorize.

٧-د) config.yml — أهمّ ملفّ #

PowerShell

@"

"@ | Out-File -FilePath "$cfDir\config.yml" -Encoding ascii -Force

🔴 ترتيب القاعدتين هو كلُّ شيء — أوّلُ مطابقةٍ تفوز. ولو سبقت قاعدةُ IIS، ذهب /api و/v إلى خادم ملفاتٍ لا يعرفهما ⇒ شاشة دخولٍ تظهر وزرٌّ لا يفعل شيئاً.

🔑 واختبر التوجيه منطقياً قبل أن تشغّل شيئاً:

PowerShell

cloudflared tunnel ingress rule https://dms.nociraq.com/v/abc               # ⇒ #0 : 5080
cloudflared tunnel ingress rule https://dms.nociraq.com/                    # ⇒ #1 : 80

كلُّها وافقت المتوقَّع في تنفيذنا — وهذا يكشف خطأ الترتيب على الورق لا بعد أن يفتح المستخدم الصفحة.

١) «٢٨ مهاجرة» والواقع ٣٠ #

⟵ اسحب لرؤية بقية الجدول ⟶

٢) الأمر شُغِّل على الجهاز الخطأ — مرّتين #

⟵ اسحب لرؤية بقية الجدول ⟶
كيف ظهر Compress-Archive على حاسبة التجربة: path ... does not exist · ثم أوامر IIS على جهازٍ بلا IIS

العلاج جدول قسمة العمل + سطرُ «أين أنا؟»

٣) .NET Runtime ليست ASP.NET Core Runtime — وفحصي كذب #

⟵ اسحب لرؤية بقية الجدول ⟶
كيف ظهر السكربت قال «مفقود»، والمستخدم قد ثبّت aspnetcore-runtime-9.0.x-win-x64 فعلاً
السبب الحقيقيّ dotnet في الـPATH كان 32-بت (C:\Program Files (x86)\dotnet) فلا يرى تثبيت x64
الأثر فحصٌ كاذب أوقف التقدّم بلا سبب
العلاج الفحص صار يُشغّل Dms.Api.exe generate-secrets — مسبارٌ آمن لا يكتب ملفاً

🔑 والدرس نظيرُ DevSigningKeysTests في المشروع: اختبارٌ لا يجرّب المنتج الحقيقيّ يحرس هيكلاً لا منتجاً. وكان العيبُ عيبي أنا، لا عيبَ الجهاز.

٤) 🔴 NT AUTHORITY\SYSTEM بلا sysadmin — أخطرُ التسعة تضليلاً #

⟵ اسحب لرؤية بقية الجدول ⟶
كيف ظهر Start-Service : Cannot start service DmsApi — بلا سبب
السجلّ SqlException: CREATE DATABASE permission denied in database 'master' · Failed executing DbCommand: CREATE DATABASE [DmsTrial];
المفارقة 🔴 القاعدة موجودةٌ فعلاً — أُنشئت قبل دقيقة!
التفسير SQL يُخفي عن الحساب قواعدَ لا يملك صلاحيةً عليها، فرآها EF غيرَ موجودة فحاول إنشاءها فرُفض
القياس الدخول موجود (is_disabled = 0) وIS_SRVROLEMEMBER('sysadmin', …) = 0
العلاج منحُ sysadmin صار خطوةً إلزامية بترقيمها (§و-3ب) بفحصٍ يثبت وقوعها

🔑 فالرسالة تتّهم «الإنشاء» والعلّة «القراءة» — ومَن يصدّقها يبحث في المكان الخطأ. ⚠️ وكان الدليل يكتبها «لو لم يفعل» بناءً على أن SQL يمنحها افتراضياً — وهو لا يمنحها. 🔑 ولماذا sysadmin لا db_owner؟ لأن RESTORE DATABASE يحتاج صلاحيةً على مستوى الخادم — وdb_owner يجعل زرّ «استعادة» يفشل يوم تحتاجه فعلاً.

٥) كلمة المرور كُتبت بيد — حرفٌ ناقص #

⟵ اسحب لرؤية بقية الجدول ⟶
كيف ظهر 400 Bad Request على /api/auth/login
السبب الكلمة ٢٠ حرفاً والمُدخَل ١٩ — والمولّد يُبقي @ # % + = ? والطرفيّة ترسم الرموز كـ?
الخطر المصاحب ⚠️ خمسُ محاولاتٍ فاشلة تقفل الحساب ١٥ دقيقة
العلاج تُقرأ من الملف ولا تُكتب بيد — فينتفي خطأ النقل تماماً
📌

و400 هنا تعني حرفياً ValidationException("اسم المستخدم أو كلمة المرور غير صحيحة") — لا عطلَ في النظام.

٦) cloudflared tunnel login — التنقّل اليدويّ لا يصل #

⟵ اسحب لرؤية بقية الجدول ⟶
كيف ظهر المستخدم في لوحة nociraq.com ولا يجد زرّ Authorize
السبب صفحة التفويض تُفتح بالرابط المطبوع في PowerShell وحده (يحمل callback)
العلاج انسخ الرابط من الطرفيّة — ولا تتنقّل في اللوحة

٧) 🔴 cloudflared service install يسجّل خدمةً فارغة #

⟵ اسحب لرؤية بقية الجدول ⟶
كيف ظهر Start-Service : Failed to start service · والموقع Error 1033 ثم 530
السجلّ Cloudflared service arguments: [C:\Program Files (x86)\cloudflared\cloudflared.exe] — بلا وسيطةٍ واحدة
التفسير بلا tunnel run وبلا --config ⇒ تُقلع، ولا تجد ما تفعله، فتخرج فوراً
علامةٌ فارقة السجلّ يكرّر service starting بلا started ولا سطرِ خطأ
العلاج كتابة ImagePath في السجلّ + config.yml بمسار اعتماد SYSTEM

⚠️ ومحاولةُ إصلاحه بـsc.exe config … binPath= فشلت — اقتباساتُه المتداخلة تتمزّق فطبع صفحة المساعدة، وBINARY_PATH_NAME بقي كما هو: 🔑 أمرٌ يبدو كأنه نجح وهو لم يفعل شيئاً. ⇒ ImagePath في السجلّ هو ما يقرؤه مدير الخدمات فعلاً — فاكتب المصدر وتجنّب المُحلِّل.

🔴 ومعه عيبٌ ثانٍ: النسخُ الحرفيّ لملفّك يُبقي credentials-file مشيراً إلى C:\Users\<أنت>\.cloudflared — وخدمةٌ بـSYSTEM تعتمد على مجلّد مستخدمٍ آخر قنبلةٌ موقوتة. عائلةُ العطل ٤ نفسها.

٩) 🔴 Stop-Website صحيحٌ للحظته وخاطئٌ للأبد #

11 11) الدروس المعمَّمة #

🔑 ١) ما ينجح بحسابك لا ينجح بحساب الخدمة #

ثلاثةٌ من التسعة (٤ · ٧ · ٩) من هذه العائلة وحدها. التشغيل اليدويّ يجري بحسابك المسؤول وفي جلستك الحالية؛ والخدمة تجري بـSYSTEM وبعد إقلاعٍ نظيف.

📌

⇒ لا تُعلن نجاح أيّ مرحلةٍ قبل إعادة تشغيلٍ واختبارٍ من جهازٍ آخر.

🔑 ٢) «يعمل الآن» غير «يبقى يعمل» #

النظام عمل تماماً من الهاتف وهو معلَّقٌ بنافذة PowerShell مفتوحة. وإغلاقُها أسقط كلَّ شيء — وهو عين ما يحدث عند إعادة التشغيل.

🔑 ٣) الفشل الصامت أخطر من الفشل الصاخب #

⟵ اسحب لرؤية بقية الجدول ⟶
العطل لماذا صامت
٧ الخدمة تُقلع وتخرج — السجلّ بلا سطر خطأ
٩ صفحةٌ تعمل وتبدو سليمة تحجب أن نظامك متوقّف
sc.exe binPath= يطبع المساعدة ويبدو كأنه نجح

🔑 ٤) اختبرْ ما يقوله الخطأ لا ما يقوله لك #

العطل ٤ اتّهم CREATE DATABASE والعلّة SELECT. والرسالة كانت صادقةً في الحرف كاذبةً في الدلالة — لأن SQL يُخفي ما لا تملكه فيبدو غيرَ موجود.

🔑 ٥) افحص المنتج لا الهيكل #

العطل ٣: سألتُ dotnet في الـPATH بدل أن أُشغّل Dms.Api.exe. والفحص الذي لا يجرّب المنتج الحقيقيّ يحرس هيكلاً لا منتجاً — وهو درسُ DevSigningKeysTests حرفياً.

🔑 ٦) اعزل المتغيّرات قبل أن تضيف واحداً #

فحصُ الدخول محلياً (507) قبل النفق جعل كلَّ عطلٍ بعده يخصّ النفق وحده — فلم نبحث في القاعدة ولا في الخدمة مرّةً واحدة.

🔑 ٧) والفحصُ على الورق أرخص من الفحص بالتشغيل #

cloudflared tunnel ingress rule أثبت التوجيه قبل أن يعمل النفق. وكلُّ فحصٍ يسبق التشغيل يوفّر دورةَ تشخيصٍ كاملة.

12 12) ما لا تُثبته التجربة #

التجربة أثبتت البرنامج والدومين والنفق والخدمات وبقاءها بعد الإقلاع. ولا تُثبت:

  • مثيل SQL Server Express المُسمّى (.\SQLEXPRESS) — حاسبتنا حملت المثيل الافتراضيّ.
  • BitLocker · الـIP الثابت · الـUPS · منع إعادة التشغيل أثناء الدوام.
  • النسخ الاحتياطي ٣-٢-١ والمرآة على القرص الخارجي.
  • 🔴 اختبار الاستعادة على جهازٍ نظيف — غيرُ قابلٍ للتفاوض، ويُنفَّذ على الـMini PC.
