تصفير الحاسبة التجريبية بالكامل (Reset to Clean State)
إزالة خدمات DmsApi و Cloudflared وموقع IIS وقاعدة DmsTrial لإعادة التجربة من الصفر
🧪 حاسبة التجربة
⚡ أمر التشغيل المؤتمت بضغطة زر:
powershell -ExecutionPolicy Bypass -File .\scripts\00-reset-trial.ps1
أوامر التصفير اليدوية المباشرة 
# إيقاف وحذف الخدمات
Stop-Service DmsApi -ErrorAction SilentlyContinue; sc.exe delete DmsApi
Stop-Service Cloudflared -ErrorAction SilentlyContinue; sc.exe delete Cloudflared

# استعادة موقع IIS الافتراضي
Import-Module WebAdministration
Remove-Website -Name "DmsApp" -ErrorAction SilentlyContinue
Set-ItemProperty "IIS:\Sites\Default Web Site" -Name serverAutoStart -Value $true
Start-Website -Name "Default Web Site"

# حذف قاعدة البيانات التجريبية
sqlcmd -S . -Q "IF EXISTS (SELECT name FROM sys.databases WHERE name = 'DmsTrial') BEGIN ALTER DATABASE DmsTrial SET SINGLE_USER WITH ROLLBACK IMMEDIATE; DROP DATABASE DmsTrial; END"

# حذف مجلد النظام وإعدادات النفق
Remove-Item -Path "C:\DMS" -Recurse -Force -ErrorAction SilentlyContinue
Remove-Item -Path "C:\Windows\System32\config\systemprofile\.cloudflared" -Recurse -Force -ErrorAction SilentlyContinue
🎯 النتيجة المتوقعة بعد التصفير:
الحاسبة تصبح نظيفة تماماً ولا يوجد فيها أي أثر لموقع DmsApp أو الخدمات، ومحرك SQL Server و IIS جاهزان للتنصيب الجديد.
⚠️ أمان البيانات:
هذا السكربت مخصص لحاسبة التجربة فقط ولا يُشغل على جهاز التطوير أو الخادم الفعلي.
01
بناء الواجهة والباك-إند وحزم الملفات (Build & Pack)
بناء الباك إند وربط الدومين المخبوز في فلاتر والتحقق الصارم من الحراس الثلاثة
💻 جهاز التطوير
⚡ تشغيل السكربت المؤتمت بالكامل (يفحص الحراس ويضغط تلقائياً):
powershell -ExecutionPolicy Bypass -File .\scripts\01-dev-build-and-pack.ps1 -Domain "dms.nociraq.com" -OutputDir "D:\DMS-نشر"
الأوامر اليدوية المفصلة 
# 1. بناء الباك إند
cd D:\DMS\backend
dotnet publish Dms.Api -c Release -r win-x64 --self-contained false -o "C:\temp\dms-publish"

# 2. بناء الواجهة بالدومين المخبوز
cd D:\DMS\app
flutter build web --release --dart-define=API_BASE_URL=https://dms.nociraq.com/api

# 3. فحص الحراس
Select-String -Path "D:\DMS\app\build\web\main.dart.js" -Pattern "dms.nociraq.com" -Quiet  # يجب True
Test-Path "C:\temp\dms-publish\ops\update-dms.ps1"                                              # يجب True
Test-Path "C:\temp\dms-publish\appsettings.Development.json"                                    # يجب False

# 4. ضغط الحزم
New-Item -ItemType Directory -Force -Path "D:\DMS-نشر" | Out-Null
Compress-Archive -Path "C:\temp\dms-publish\*"  -DestinationPath "D:\DMS-نشر\dms-api.zip" -Force
Compress-Archive -Path "D:\DMS\app\build\web\*" -DestinationPath "D:\DMS-نشر\dms-app.zip" -Force
🎯 الحارس الإلزامي:
• فحص الدومين داخل main.dart.js يجب أن يعيد True.
• فحص appsettings.Development.json يجب أن يعيد False لمنع تسريب المفاتيح.
• أحجام الحزم الناتجة يجب أن تتجاوز 5 ميغابايت لكل ملف.
⚠️ درس من واقع التجربة (العطل 2):
هذه الخطوة على جهاز التطوير حصراً. ضغط الحزم على حاسبة التجربة سيفشل لعدم وجود مجلدات الكود.
02
فك الحزم على حاسبة التجربة (Unpack)
نقل الحزم عبر الفلاشة وفكها إلى C:\DMS\api و C:\DMS\app
🧪 حاسبة التجربة
⚡ تشغيل السكربت المؤتمت:
powershell -ExecutionPolicy Bypass -File .\scripts\02-trial-unpack.ps1 -SourceDrive "E:\"
الأوامر اليدوية المباشرة 
New-Item -ItemType Directory -Force -Path C:\DMS\api, C:\DMS\app | Out-Null
Expand-Archive -Path "E:\dms-api.zip" -DestinationPath "C:\DMS\api" -Force
Expand-Archive -Path "E:\dms-app.zip" -DestinationPath "C:\DMS\app" -Force
🎯 الحارس:
تأكد من وجود الملفات C:\DMS\api\Dms.Api.exe و C:\DMS\app\web.config.
⚠️ تنبيه هندسي:
Expand-Archive لا يحذف القديم، لذلك السكربت يقوم بتفريغ C:\DMS\app تلقائياً لمنع تداخل النسخ.
03
الفحص المسبق للحاسبة (Pre-flight Check)
فحص بيئة ASP.NET Core Runtime ومثيل SQL والمنافذ الشاغرة
🧪 حاسبة التجربة
⚡ تشغيل سكربت الفحص المسبق الشامل:
powershell -ExecutionPolicy Bypass -File .\scripts\03-trial-preflight.ps1 -Domain "dms.nociraq.com" -DbName "DmsTrial"
المسبار الحاسم لفحص ASP.NET Core Runtime (علاج العطل 3) 
C:\DMS\api\Dms.Api.exe generate-secrets
🎯 الناتج المتوقع للمسبار:
يجب أن يطبع الاستخدام: Dms.Api.exe generate-secrets --out ... (هذا يثبت سلامة بيئة الدوت نت x64 الحقيقية).
⚠️ درس العطل 3:
لا تسأل dotnet في الـ PATH لأنه قد يكون 32-بت فيعطيك فشلاً كاذباً بينما البرنامج x64 سليم تماماً!
04
توليد الأسرار وتهيئة قاعدة البيانات (Secrets & DB)
توليد أسرار الإنتاج، منح sysadmin لحساب SYSTEM، أول إقلاع، وفحص الدخول المحلي
🧪 حاسبة التجربة
⚡ تشغيل السكربت المؤتمت (يولد الأسرار ويضبط الصلاحيات ويفحص المهاجرات):
powershell -ExecutionPolicy Bypass -File .\scripts\04-trial-secrets-and-db.ps1 -Domain "dms.nociraq.com" -DbServer "." -DbName "DmsTrial"
أمر منح صلاحية sysadmin لحساب SYSTEM الحاسم (علاج العطل 4) 
sqlcmd -S . -Q "IF NOT EXISTS (SELECT 1 FROM sys.server_principals WHERE name = 'NT AUTHORITY\SYSTEM') CREATE LOGIN [NT AUTHORITY\SYSTEM] FROM WINDOWS; ALTER SERVER ROLE sysadmin ADD MEMBER [NT AUTHORITY\SYSTEM];"
sqlcmd -S . -Q "SELECT IS_SRVROLEMEMBER('sysadmin', 'NT AUTHORITY\SYSTEM') AS IsSysadmin;"   # يجب 1
🎯 الحراس:
• IsSysadmin يجب أن يساوي 1.
• فحص الدخول المحلي /api/auth/login يعيد رمز توكن بطول 507 تقريباً.
⚠️ درس العطل 4 و 5:
• بدون sysadmin لحساب SYSTEM ستفشل الخدمة صامتاً بدعوى أن القاعدة غير موجودة.
• كلمة المرور تُقرأ من الملف برمجياً ولا تكتب باليد تجنباً للخطأ الإملائي وقفل الحساب.
05
تثبيت وضبط خدمة DmsApi (Windows Service)
تسجيل الخدمة وضبط تبعيتها لمثيل SQL والتعافي التلقائي وحقن متغير البيئة
🧪 حاسبة التجربة
⚡ تشغيل سكربت تثبيت الخدمة:
powershell -ExecutionPolicy Bypass -File .\scripts\05-trial-service-setup.ps1
أوامر التثبيت اليدوية 
sc.exe create DmsApi binPath= "C:\DMS\api\Dms.Api.exe" start= auto DisplayName= "DMS API Service"
sc.exe config DmsApi depend= 'MSSQLSERVER'
sc.exe failure DmsApi reset= 86400 actions= restart/30000/restart/30000/restart/60000
Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\DmsApi" `
    -Name "Environment" -Value @("ASPNETCORE_ENVIRONMENT=Production") -Type MultiString

Start-Service DmsApi
Invoke-RestMethod -Uri "http://localhost:5080/api/system/status"   # maintenance : False
🎯 الحارس:
طلب http://localhost:5080/api/system/status يرد بـ JSON فيه maintenance: false.
⚠️ تنبيه التبعية (depend):
استخدم اسم مثيلك الفعلي (MSSQLSERVER أو MSSQL$SQLEXPRESS).
06
ضبط خادم IIS وموقع DmsApp (علاج العطل 9)
إيقاف Default Web Site ومنع إقلاعه، إنشاء موقع DmsApp، وفحص canvaskit.wasm
🧪 حاسبة التجربة
⚡ تشغيل سكربت إعداد IIS وفحص CanvasKit:
powershell -ExecutionPolicy Bypass -File .\scripts\06-trial-iis-setup.ps1
الأوامر اليدوية المباشرة 
Import-Module WebAdministration

# 🔴 يُعطَّل عن الإقلاع التلقائي لمنع احتلال المنفذ 80 (العطل 9)
Stop-Website -Name "Default Web Site" -ErrorAction SilentlyContinue
Set-ItemProperty "IIS:\Sites\Default Web Site" -Name serverAutoStart -Value $false

New-Website -Name "DmsApp" -Port 80 -PhysicalPath "C:\DMS\app" -Force
Set-ItemProperty "IIS:\Sites\DmsApp" -Name serverAutoStart -Value $true
Start-Website -Name "DmsApp"

icacls "C:\DMS\app" /grant "IIS_IUSRS:(OI)(CI)(RX)"

# الفحص الحاسم لملفات الرسم
(Invoke-WebRequest "http://localhost/canvaskit/canvaskit.wasm" -UseBasicParsing).StatusCode   # يجب 200
🎯 الحارس الحاسم:
• Default Web Site = Stopped / False.
• DmsApp = Started / True.
• تحميل canvaskit.wasm يعيد كود 200 لمنع ظهور صفحة بيضاء.
⚠️ أخبث الأعطال (العطل 9):
لو لم تضع serverAutoStart = $false، سيسبق الموقع الافتراضي بعد إعادة التشغيل ويحتل المنفذ 80 فتظهر صفحة IIS الزرقاء للمستخدمين!
07
نفق Cloudflare وتثبيته كخدمة (علاج العطل 7)
إنشاء النفق وضبط التوجيه بالريجكس ونقل الإعدادات لـ SYSTEM وتصحيح ImagePath
🧪 حاسبة التجربة
⚡ تشغيل سكربت النفق المتكامل وحل ثغرة الخدمة الفارغة:
powershell -ExecutionPolicy Bypass -File .\scripts\07-trial-tunnel-setup.ps1 -Domain "dms.nociraq.com"
قواعد التوجيه الدقيقة في config.yml 
ingress:
  - hostname: dms.nociraq.com
    path: "^/(api|v)(/|$)"
    service: http://localhost:5080

  - hostname: dms.nociraq.com
    service: http://localhost:80

  - service: http_status:404
🎯 الحارس:
• cloudflared tunnel ingress validate يعيد نجاح الفحص.
• sc.exe qc Cloudflared يجب أن ينتهي بـ tunnel run.
⚠️ درس العطل 7 (الخدمة الفارغة):
أمر cloudflared service install يسجل خدمة فارغة بدون معاملات فتسقط فوراً! السكربت يكتب مسار ImagePath الصحيح في الريجستري مباشرة.

powershell -ExecutionPolicy Bypass -File .\scripts\08-trial-verify-final.ps1 -Domain "dms.nociraq.com"
